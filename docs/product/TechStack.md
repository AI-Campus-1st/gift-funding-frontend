## 2. 프론트엔드

### 2.1 Next.js + React + TypeScript

- Next.js로 페이지 라우팅과 웹 서비스 구조를 관리한다.
- React 컴포넌트로 재사용 가능한 화면 요소를 구성한다.
- TypeScript로 API 요청·응답 데이터와 UI 상태의 타입을 관리한다.
- 모바일 우선 반응형 웹으로 개발한다.
- 로그인 여부에 따라 접근 가능한 페이지를 구분한다.
- 초대 링크 접속 시 로그인 상태를 확인하고 참여 화면으로 연결한다.

**주요 화면**

- 랜딩
- 회원가입
- 로그인
- 홈
- 내 펀딩
- 그룹
- 친구 펀딩
- 마이페이지

**주요 세부 화면**

- AI 선물 추천
- 그룹 생성 및 초대
- 펀딩 생성
- 선물 등록 및 수정
- 펀딩 상세 및 관리
- 선물 후원 및 완료
- 축하 메시지 카드
- 축하 편지함
- 목표 미달 처리
- 정산 관리
- 생일 캘린더
- 알림

### 2.2 Tailwind CSS + shadcn/ui + Lucide React

- Tailwind CSS로 레이아웃과 반응형 스타일을 구현한다.
- shadcn/ui로 공통 폼, 버튼, 카드, 모달 등을 구성한다.
- Lucide React로 일관된 아이콘을 적용한다.
- 컬러, 폰트, 컴포넌트 스타일은 `base.md`를 따른다.
- Y2K 핑크 레트로 및 Windows 98 스타일을 적용한다.
- 모바일 화면에서는 전체 너비를 사용한다.
- 데스크톱에서는 앱 영역을 최대 430px 너비로 중앙 배치한다.

**주요 공통 컴포넌트**

- Button
- Input
- Textarea
- Dialog
- Card
- Progress
- Calendar / Date Picker
- Form
- Select
- Tabs
- Toast / Alert
- Badge

### 2.3 친구 펀딩 UI

**적용 기술**
- Next.js
- React
- TypeScript
- shadcn/ui

**구현 기능**
- 친구 펀딩 목록
- 진행 중 / 종료된 펀딩 구분
- 초대 링크 입력 모달
- 초대 링크 유효성 확인
- 참여 대상 정보 표시
- 참여하기 버튼
- 친구 펀딩 상세 화면
- 본인 후원 내역 화면

**구현 기준**
- "+ 친구 펀딩 참여하기" 버튼을 제공한다.
- 버튼 클릭 시 초대 링크 입력 모달을 표시한다.
- 입력한 링크를 백엔드 API로 검증한다.
- 검증 결과에 따라 그룹 이름, 펀딩 이름, 생일자 이름을 표시한다.
- 참여 완료 시 친구 펀딩 상세 화면으로 이동한다.
- 이미 참여한 펀딩은 중복 등록하지 않고 상세 화면으로 이동한다.
- 참여 중인 펀딩이 없으면 빈 상태 안내를 표시한다.
- 접근 권한이 없는 펀딩은 화면에 표시하지 않는다.

### 2.4 후원 금액 선택 UI

**적용 기술**
- React
- TypeScript
- shadcn/ui

**구현 기능**
- 추천 후원 금액 버튼
- 직접 입력창
- 선택한 후원 금액 표시
- 후원 금액 유효성 검사
- 초과 후원 오류 안내
- 후원하기 버튼
- 후원 완료 화면 이동

**구현 기준**
- 추천 금액 버튼은 5,000원, 10,000원, 30,000원을 제공한다.
- 직접 입력으로 원하는 후원 금액을 설정할 수 있다.
- 입력 금액은 원화 정수로 처리한다.
- 후원 금액은 0원보다 커야 한다.
- 선택한 금액에 따라 버튼 문구를 변경한다.
- 버튼 문구는 "{선택한 금액}원 후원하기"로 표시한다.
- 후원 금액이 유효하지 않으면 버튼을 비활성화한다.
- 후원 처리 중에는 중복 클릭을 방지한다.
- 후원 성공 응답을 받은 경우에만 완료 화면으로 이동한다.
- 후원 실패 시 입력한 금액과 메시지를 유지한다.

**초과 후원 처리**
- 백엔드에서 최대 후원 가능 금액을 반환한다.
- 프론트엔드에서 해당 금액을 오류 문구에 표시한다.
- 기본 화면에서는 실제 전체 모금액과 남은 모금액을 표시하지 않는다.

### 2.5 축하 메시지 카드 UI

**적용 기술**
- React
- TypeScript
- Tailwind CSS
- shadcn/ui

**구현 기능**
- 축하 메시지 카드
- 추천 축하 문구 버튼
- 메시지 직접 입력창
- 메시지 미리보기
- 메시지 수정 및 삭제
- 메시지 없이 후원하기

**구현 기준**
- 축하 메시지 카드는 후원 금액 선택 화면에 포함한다.
- 별도의 필수 메시지 작성 화면을 만들지 않는다.
- 추천 문구 버튼 클릭 시 입력창에 해당 문구를 자동 입력한다.
- 자동 입력된 문구는 수정하거나 삭제할 수 있다.
- 메시지는 선택사항이다.
- 후원하기 버튼 클릭 시 작성한 메시지를 후원 요청에 함께 포함한다.
- 메시지가 비어 있으면 메시지 없이 후원을 진행한다.
- 후원 완료 후 별도의 메시지 작성 단계로 이동하지 않는다.

**추천 문구**
- "생일 축하해! 🎂"
- "태어나줘서 고마워 💗"
- "오늘 하루 행복하게 보내! 🎉"
- "항상 좋은 일만 가득하길 ✨"

### 2.6 FullCalendar

- 생일 일정에 연결된 펀딩으로 이동할 수 있다.
- 캘린더에 표시할 생일과 접근 가능한 펀딩 정보는 백엔드 API로 조회한다.

## 3. 백엔드

### 3.1 Python + FastAPI

- 회원 인증, 그룹, 펀딩, 선물, 후원, 정산 상태, 메시지, 알림을 위한 REST API를 제공한다.
- 펀딩별 생일자와 후원자 권한을 서버에서 검사한다.
- 회원가입 시 계정 역할을 별도로 구분하지 않는다.
- Pydantic으로 요청·응답 데이터 형식을 검증한다.
- Swagger UI로 API를 확인하고 테스트한다.

**주요 API 기능**

- 회원가입 및 로그인
- 프로필 조회 및 수정
- AI 선물 추천
- 그룹 생성 및 관리
- 초대 링크 생성 및 검증
- 그룹 또는 펀딩 참여
- 친구 펀딩 목록 조회
- 펀딩 생성 및 관리
- 선물 등록 및 수정
- 후원 요청 및 처리
- 본인 후원 내역 조회
- 축하 메시지 저장 및 조회
- 목표 미달 처리
- 정산 상태 관리
- 생일 캘린더
- 알림 관리

### 3.2 초대 링크 및 참여 처리

**적용 기술**
- FastAPI
- Pydantic
- SQLAlchemy
- PostgreSQL
- JWT
- Python secrets

**구현 기준**
- 그룹 또는 펀딩별 초대 토큰을 생성한다.
- 초대 토큰은 예측하기 어려운 값으로 생성한다.
- 초대 링크의 유효성 및 활성화 상태를 검증한다.
- 만료 정책이 설정된 링크는 만료 여부를 확인한다.
- 로그인한 사용자만 최종 참여를 완료할 수 있다.
- 참여 대상 그룹 또는 펀딩 정보를 제공한다.
- 참여 요청 시 사용자 권한을 검증한다.
- 동일 그룹 또는 펀딩에 대한 중복 참여를 방지한다.
- 참여 완료 후 친구 펀딩 목록에 반영한다.
- 그룹 참여 권한과 개별 펀딩 접근 권한을 구분한다.
- 초대 링크를 통해 권한이 없는 다른 펀딩을 조회할 수 없도록 한다.

### 3.3 후원 금액 검증 및 처리

**적용 기술**
- FastAPI
- Pydantic
- SQLAlchemy
- PostgreSQL

**구현 기준**
- 후원 금액은 0원보다 큰 정수여야 한다.
- 후원 요청 시 최신 모금 상태를 조회한다.
- 목표 금액과 현재 모금액을 비교한다.
- 남은 모금액을 초과하는 요청은 거부한다.
- 초과 후원 오류 응답에 최대 후원 가능 금액을 포함한다.
- 후원 처리 성공 시 모금 상태를 갱신한다.
- 목표 금액을 달성한 선물은 추가 후원을 차단한다.
- 펀딩 기간이 종료된 경우 후원을 차단한다.
- 동시 후원 요청으로 목표 금액을 초과하지 않도록 트랜잭션을 적용한다.
- 동일 요청의 중복 처리를 방지한다.
- 동일 사용자가 새로운 요청으로 다시 후원하는 것은 허용한다.

**동시 후원 처리 방식**
- PostgreSQL 트랜잭션을 사용한다.
- 필요한 후원 대상 행에 행 수준 잠금 등을 적용한다.
- 최신 모금액을 확인한 후 후원 가능 여부를 검증한다.
- 검증과 후원 기록 저장 및 모금액 갱신을 하나의 트랜잭션으로 처리한다.
- 중복 요청 식별자에 고유 제약조건을 적용한다.
- 동시 요청 충돌 시 최신 상태를 기준으로 재검증한다.

### 3.4 권한별 API 응답

**적용 기술**
- FastAPI
- Pydantic
- JWT
- SQLAlchemy

**구현 기준**
- 생일자용 응답과 후원자용 응답을 구분한다.
- 생일자에게는 실제 전체 모금액과 남은 모금액을 제공한다.
- 생일자에게는 후원자 이름과 개별 후원 금액 및 내역을 제공한다.
- 후원자에게는 선물 이름, 이미지, 실제 가격, 목표 금액, 상품 구매 URL을 제공한다.
- 후원자에게는 목표 달성률(%) 및 진행률 바 표시용 데이터를 제공한다.
- 후원자용 일반 조회 응답에는 실제 전체 모금액과 남은 모금액을 포함하지 않는다.
- 후원자에게는 본인의 후원 내역만 제공한다.
- 다른 후원자의 개별 후원 금액 및 내역은 제공하지 않는다.
- 후원 금액 초과 오류 응답에만 최대 후원 가능 금액을 포함한다.
- 축하 메시지는 해당 펀딩의 생일자에게만 제공한다.
- 정산 정보는 해당 펀딩의 생일자에게만 제공한다.
- 모든 권한 검사는 서버에서 수행한다.

### 3.5 축하 메시지 처리

**적용 기술**
- FastAPI
- Pydantic
- SQLAlchemy
- PostgreSQL

**구현 기준**
- 후원 요청 데이터에 선택적 축하 메시지 필드를 포함한다.
- 메시지가 없는 경우 메시지 레코드를 생성하지 않는다.
- 메시지가 있는 경우 후원 정보와 연결하여 저장한다.
- 작성자 이름은 인증된 사용자 계정 정보를 사용한다.
- 클라이언트가 전달한 임의의 작성자 이름을 신뢰하지 않는다.
- 메시지에 후원 금액을 자동 포함하지 않는다.
- 후원 기록과 메시지 저장의 데이터 일관성을 유지한다.
- 후원 처리 실패 시 메시지만 저장되는 상황을 방지한다.
- 생일자 전용 메시지 조회 API를 제공한다.
- 다른 후원자의 메시지 조회 요청은 거부한다.

### 3.6 SQLAlchemy + Alembic

- SQLAlchemy로 PostgreSQL 모델과 쿼리를 관리한다.
- Alembic으로 테이블 및 컬럼 변경 이력을 관리한다.
- 그룹 참여, 펀딩 참여, 후원 요청 식별자 등에 필요한 고유 제약조건을 설정한다.
- 후원 한도, 중복 요청, 정산·이월 중복 처리 방지에 데이터베이스 트랜잭션과 제약조건을 활용한다.
- 외래 키를 통해 회원, 그룹, 펀딩, 선물, 후원, 메시지 간 관계를 관리한다.

### 3.7 APScheduler

- 설정된 펀딩 종료일에 따른 상태 갱신을 처리한다.
- 생일 하루 전과 당일의 서비스 내부 알림 생성 작업을 처리한다.
- 작업 재실행 시 중복 알림이나 중복 상태 변경이 발생하지 않도록 구현한다.
- 서버 재시작 후에도 데이터베이스 상태를 기준으로 필요한 작업을 확인한다.
- 스케줄러가 중복 실행되지 않도록 실행 환경을 구성한다.
- 후원 요청 시에도 서버에서 펀딩 종료 여부를 직접 확인한다.

## 4. 데이터베이스 — PostgreSQL

### 4.1 저장 데이터

- 회원 정보
- 프로필 및 관심 키워드
- 그룹 정보
- 그룹 참여 정보
- 그룹 또는 펀딩 초대 정보
- 펀딩 참여 정보
- 펀딩 정보
- 선물 정보
- 후원 정보
- 후원 요청 식별 정보
- 축하 메시지
- 정산 상태 및 이력
- 이월 기록
- 생일 일정
- 알림 정보

### 4.2 주요 데이터 관계

- 하나의 회원은 여러 그룹에 참여할 수 있다.
- 하나의 회원은 여러 펀딩을 생성할 수 있다.
- 하나의 회원은 여러 친구 펀딩에 참여할 수 있다.
- 하나의 그룹에는 여러 펀딩이 연결될 수 있다.
- 하나의 펀딩에는 여러 선물이 등록될 수 있다.
- 하나의 선물에는 여러 후원 기록이 연결될 수 있다.
- 하나의 후원에는 선택적으로 축하 메시지가 연결될 수 있다.
- 하나의 펀딩에는 하나의 생일자가 연결된다.
- 그룹 관리자와 펀딩 생일자는 별도 권한으로 관리한다.

### 4.3 금액 데이터

- 후원 금액은 원화 정수 단위로 저장한다.
- 선물 가격을 선물별 목표 금액으로 사용한다.
- 선물별 현재 모금액을 관리한다.
- 선물별 남은 모금액과 달성률을 계산한다.
- 여러 선물의 목표 금액을 하나의 통합 목표 금액으로 합산하지 않는다.
- 후원 금액은 목표 금액을 초과할 수 없다.
- 실제 금전 거래 구현 시 결제 승인 상태와 정상 처리된 후원 금액을 구분한다.

### 4.4 데이터 무결성

- 회원 이메일 중복을 방지한다.
- 동일 사용자의 그룹 중복 참여를 방지한다.
- 동일 사용자의 펀딩 중복 참여를 방지한다.
- 동일 후원 요청 식별자의 중복 처리를 방지한다.
- 의도적으로 발생한 서로 다른 후원 요청은 허용한다.
- 정산 및 이월 대상 금액의 중복 처리를 방지한다.
- 후원과 메시지 저장은 일관성 있게 처리한다.
- 정산 및 이월 상태 변경은 트랜잭션으로 처리한다.

> 실제 테이블명, 컬럼, 관계 및 API 엔드포인트는 데이터베이스·API 설계 단계에서 정의한다. 기능별 정책은 `feature_spec.md`를 따른다.

## 5. AI — OpenAI API + httpx

- 사용자 관심 키워드, 취향, 예산 등으로 선물 아이디어를 추천한다.
- FastAPI에서 OpenAI API를 호출하고 추천 결과를 프론트엔드에 전달한다.
- 추천 결과에는 선물 이름, 추천 이유, 예상 가격대, 카테고리 등을 포함한다.
- 추천 결과는 참고용으로 사용한다.
- 추천된 상품의 실제 가격, 이미지, 판매 링크는 사용자가 확인한 뒤 등록한다.
- AI가 추천한 상품을 자동으로 구매하거나 등록하지 않는다.
- AI 응답 실패·지연·부정확한 상품 정보에 대한 예외 처리를 구현한다.
- AI 응답 데이터는 Pydantic 등을 통해 필요한 형식을 검증한다.
- API 키는 서버 측 환경 변수로 관리한다.
- 클라이언트에 API 키를 노출하지 않는다.

## 6. 인증 및 보안

| 기술 / 방식 | 적용 목적 |
|---|---|
| JWT | 로그인 인증 토큰 처리 |
| pwdlib / Argon2 | 비밀번호 해싱 및 검증 |
| HTTPS | 클라이언트–서버 통신 보호 |
| 서버 측 권한 검사 | 그룹 및 펀딩별 접근 제한 |
| Python secrets | 예측하기 어려운 초대 토큰 생성 |
| Pydantic | API 입력값 및 응답 형식 검증 |
| PostgreSQL 트랜잭션 | 후원 및 정산 데이터 일관성 |
| 고유 제약조건 | 중복 참여 및 중복 후원 요청 방지 |
| 환경 변수 | API 키, DB 접속 정보 등 비밀값 관리 |

### 6.1 인증

- 로그인한 사용자만 펀딩 생성 및 후원을 진행할 수 있다.
- 보호된 API 요청 시 JWT를 검증한다.
- 회원가입 시 생일자와 후원자 역할을 고정하지 않는다.
- 펀딩별 소유자 및 참여자 관계를 기준으로 권한을 확인한다.
- 초대 링크로 접속한 사용자가 로그인하지 않았다면 로그인 후 참여 과정을 이어서 진행한다.

### 6.2 권한 관리

- 본인 펀딩의 실제 모금액과 정산 정보는 생일자만 조회할 수 있다.
- 후원자는 참여 권한이 있는 친구 펀딩만 조회할 수 있다.
- 후원자는 본인 후원 내역만 조회할 수 있다.
- 다른 후원자의 개별 후원 금액 및 내역은 조회할 수 없다.
- 축하 메시지는 해당 펀딩의 생일자만 조회할 수 있다.
- 그룹 관리 기능은 그룹 관리자에게만 제공한다.
- 화면에서 숨기는 것만으로 처리하지 않고 API 응답에서도 비공개 데이터를 제외한다.

### 6.3 초대 링크 보안

- 초대 토큰은 예측하기 어려운 난수로 생성한다.
- 초대 링크의 유효성 및 활성화 상태를 검증한다.
- 초대 링크 비활성화 기능을 제공한다.
- 참여 완료 전 사용자 인증 및 권한 검사를 수행한다.
- 초대 링크를 통해 다른 비공개 그룹이나 펀딩 정보가 노출되지 않도록 한다.
- 초대 토큰은 필요한 범위에서만 사용하고 불필요한 로그 노출을 방지한다.

### 6.4 후원 처리 보안

- 후원 금액은 서버에서 최종 검증한다.
- 후원 금액은 0원보다 큰 정수여야 한다.
- 목표 금액 초과 후원을 방지한다.
- 펀딩 종료 후 후원을 차단한다.
- 동일 요청의 중복 처리를 방지한다.
- 동시 요청 시 트랜잭션으로 금액 일관성을 유지한다.
- 초과 후원 시 최대 가능 금액만 오류 응답으로 제공한다.
- 일반 후원 조회 API에서는 실제 전체 모금액과 남은 모금액을 제공하지 않는다.

### 6.5 개인정보 및 비밀값 관리

- 비밀번호는 Argon2 기반으로 해싱하여 저장한다.
- 비밀번호 원문을 데이터베이스에 저장하지 않는다.
- API 키와 DB 접속 정보는 환경 변수로 관리한다.
- `.env` 등 비밀값 파일은 Git 저장소에 포함하지 않는다.
- 사용자 계좌 정보는 필요한 권한에서만 접근하도록 제한한다.
- 실제 결제 및 정산 도입 시 별도의 보안·개인정보 처리 기준을 확정한다.

- SMTP 또는 이메일 API는 서비스 내부 알림 외에 이메일 알림을 확장할 때 검토한다.

### 10.4 구현 범위 확인이 필요한 기술

- 실제 카드 결제 및 계좌이체

- 본인 명의 계좌 인증
- 실제 후원금 보관 및 이월
- 결제 취소 및 환불
- 결제 및 정산 수수료 처리

실제 결제와 송금이 MVP 범위에 포함되지 않는 경우에는 PostgreSQL 기반 모의 후원 및 모의 정산으로 구현한다.

실제 금전 거래를 구현하는 경우에는 결제 서비스 제공업체, 정산 방식, 보안 정책 및 관련 운영 요건을 별도로 확정한다.
