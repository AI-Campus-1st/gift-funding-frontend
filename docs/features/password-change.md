## 1. 목적

로그인한 사용자가 **마이페이지에서 자기 비밀번호를 바꿀 수 있게** 한다. 지금은 회원가입 때 정한 비밀번호를 바꿀 방법이 없다.

## 2. 확정 정책 (2026-10-21)

| # | 정책 | 결정 |
|---|---|---|
| P1 | 현재 비밀번호 확인 | **입력받는다.** 현재 비밀번호가 맞아야 바꿀 수 있다 (다른 사람이 로그인된 기기로 몰래 바꾸는 것 방지) |
| P2 | 이전 비밀번호 재사용 | **지금 쓰는 비밀번호와 같은 비밀번호로는 바꿀 수 없다.** (예전 비밀번호 기록은 저장하지 않는다 → DB 변경 없음) |
| P3 | 바꾼 뒤 로그인 | **로그인 유지.** 안내 메시지만 보여 주고 마이페이지로 돌아간다 |
| P4 | 새 비밀번호 규칙 | 회원가입과 같다: **8자 이상** |

## 3. 화면 (UI)

- 진입: 마이페이지 메뉴 **"비밀번호 변경"** → `/change-password`
- 입력 칸 3개 — 모두 **보기 / 숨기기 버튼** (로그인 화면과 같은 방식)

| 칸 | 검사 | 안내 문구 |
|---|---|---|
| 현재 비밀번호 | 비어 있음 | 현재 비밀번호를 입력해 주세요. |
| | 틀림 (서버) | 현재 비밀번호가 일치하지 않습니다. |
| 새 비밀번호 | 비어 있음 | 비밀번호를 입력해 주세요. |
| | 8자 미만 | 비밀번호는 8자 이상 입력해 주세요. |
| | 현재 비밀번호와 같음 | 현재 비밀번호와 다른 비밀번호를 입력해 주세요. |
| 새 비밀번호 확인 | 비어 있음 | 비밀번호를 다시 입력해 주세요. |
| | 새 비밀번호와 다름 | 비밀번호가 일치하지 않습니다. |

- 성공: 토스트 **"비밀번호를 변경했어요."** → 마이페이지로 이동
- 저장 중에는 버튼을 다시 누를 수 없다. 실패하면 입력값을 유지한다.

## 4. API — A8 `PATCH /me/password`

**Request**
```json
{ "current_password": "password123", "new_password": "newpass1234", "new_password_confirm": "newpass1234" }
```
**Response** `204` (본문 없음)

**처리 순서**
1. 로그인 확인 (없으면 `401 UNAUTHORIZED`)
2. 입력 검사 — 비어 있음 · 8자 미만 · 확인 불일치 → `400 VALIDATION` + `field_errors`
3. 현재 비밀번호 확인 (Argon2 검증) → 틀리면 `400 VALIDATION` `field_errors.current_password` "현재 비밀번호가 일치하지 않습니다."
   - ⚠️ `401`을 쓰지 않는다: 프론트는 `401`을 "로그인 만료"로 보고 로그아웃시키기 때문
4. 새 비밀번호가 현재 비밀번호와 같음 → `400 VALIDATION` `field_errors.new_password` "현재 비밀번호와 다른 비밀번호를 입력해 주세요."
5. `users.password_hash`를 새 Argon2 해시로 저장 → `204`

## 5. 영향 분석

| 영역 | 영향 | 조치 |
|---|---|---|
| DB | **변경 없음.** `users.password_hash` 값만 바뀐다 | `docker compose down -v` 필요 없음 |
| 로그인 (A2) | 바꾼 뒤에는 새 비밀번호로만 로그인된다 | 테스트로 확인 |
| 로그인 토큰 | 이미 발급된 토큰은 유효기간(30일)까지 그대로 → **다른 기기의 로그인도 유지된다** (서버가 토큰을 저장하지 않는 구조, PENDING L4) | 지금은 그대로 두고 PENDING에 기록 |
| 다른 기능 | 펀딩 · 후원 · 정산 · 알림 · AI — 영향 없음 | 기존 테스트 전체 통과로 확인 |
| 프론트 | 화면 1개 · 마이페이지 메뉴 1줄 추가 | Mock 서버에도 같은 API (프론트 테스트가 Mock 위에서 돈다) |
| 보안 | 현재 비밀번호 확인 후에만 변경. 비밀번호 원문은 저장 · 로그 · 응답에 남기지 않는다 | — |
