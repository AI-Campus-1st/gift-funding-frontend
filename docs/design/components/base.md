
# base.md — AI 기반 생일선물 공동 펀딩 플랫폼 디자인 시스템

> 문서 상태: 디자인 기준안 · 버전: 1.2 · 수정일: 2026-10-14  
> 목적: 서비스의 모든 화면과 프론트엔드 구현에 공통으로 적용할 디자인 기준 정의  
> 참고 자료: 핑크 Y2K 레트로 웹 이미지, Windows 98 UI 스타일, 확정된 서비스 기능명세서 및 사용자 시나리오

> 이 문서는 참고 디자인을 그대로 복제하지 않는다. 색상 코드와 수치는 참고 이미지의 실측값이 아닌 프로젝트 디자인 기준값이다.

---

## 1. 디자인 개요

### 1.1 서비스와 디자인 방향

- **서비스:** 생일자가 선물을 1개 이상 등록하고, 초대받은 친구와 지인들이 원하는 선물에 자유로운 금액으로 후원하는 비공개 생일선물 공동 펀딩 플랫폼.
- **디자인 콘셉트:** Y2K 핑크 레트로 웹 + Windows 98 스타일의 창 + 귀여운 키치 감성.
- **시각 요소:** 핑크·라벤더·하늘색, 창 제목 표시줄, 픽셀풍 테두리, 하트·별·나비·편지봉투·CD 스티커, 은은한 홀로그램 그라데이션.
- **디자인 우선순위:** 사용성, 가독성, 접근성을 우선하고 레트로 장식은 보조적으로 사용한다.
- **브랜드 체계:** 하나의 브랜드 컬러 시스템을 사용하며 별도의 서브 브랜드는 정의하지 않는다.
- **핵심 경험:** 생일 위시리스트와 공동 후원 과정을 레트로 컴퓨터 창에서 진행하는 듯한 경험을 제공한다.
- **서비스 형태:** 모바일 우선 반응형 웹앱. 데스크톱 브라우저에서도 모바일 앱 형태로 표시한다.

### 1.2 반드시 지켜야 하는 서비스 정책

1. 생일자는 선물을 최소 1개 이상 등록할 수 있다.
2. 각 선물은 실제 가격과 동일한 독립적인 목표 금액을 가진다.
3. 그룹과 펀딩은 비공개이며 참여 권한이 있는 사용자만 조회할 수 있다.
4. 후원자는 선물 이름, 이미지, 실제 가격, 목표 금액, 상품 구매 URL, 달성률 및 진행률 바를 확인할 수 있다.
5. 후원자는 실제 전체 모금액과 남은 모금액, 다른 후원자의 개별 후원 금액 및 내역을 확인할 수 없다.
6. 생일자는 실제 전체 모금액, 남은 모금액, 후원자별 금액 및 내역을 확인할 수 있다.
7. 후원자는 본인의 후원 금액과 내역을 확인할 수 있다.
8. 후원 금액이 남은 모금액을 초과하면 정확한 최대 후원 가능 금액을 안내한다.
9. 목표 금액을 달성한 선물과 기간이 종료된 펀딩에는 추가 후원할 수 없다.
10. 동일 사용자의 의도적인 반복 후원은 허용하되 동일 요청의 중복 처리는 방지한다.
11. 목표 미달 시 생일자는 `다음 생일로 이월` 또는 `현재 모금액 인출` 중 하나만 선택한다.
12. 플랫폼은 선물을 직접 구매하거나 배송하지 않는다.
13. 축하 메시지는 후원 금액 입력 화면에서 선택적으로 작성한다.
14. 축하 메시지는 실제 계정 이름으로 작성하며 생일자만 볼 수 있다.
15. 후원 성공 시 완료 화면으로 자동 이동한다.
16. 실제 결제·정산을 모의 처리하는 경우 반드시 `모의 후원`, `모의 정산`임을 명확하게 표시한다.

- 금액 입력창, 중요한 오류 메시지, 정산 정보 뒤에는 복잡한 장식 배경을 사용하지 않는다.
- 목표 달성은 성공 색상과 `100% 달성` 문구를 함께 표시한다.
- 오류는 빨간색과 구체적인 해결 안내를 함께 표시한다.

## 3. 타이포그래피

### 3.1 폰트

- 모든 실제 UI 글씨에 **Pretendard**를 사용한다.
- 한글, 영문, 숫자에 동일한 기본 폰트를 적용한다.
- 기본 폰트 선언:

```css
font-family: Pretendard, -apple-system, BlinkMacSystemFont,
  "Apple SD Gothic Neo", "Noto Sans KR", sans-serif;
```

- Airbnb Cereal, Circular 및 유료 레트로 폰트는 사용하지 않는다.
- Y2K 분위기는 창 제목 표시줄, 테두리, 그림자, 스티커, 장식 이미지로 표현한다.
- 중요한 UI 문구에 장식용 폰트를 사용하지 않는다.

### 3.2 글씨 크기 및 굵기

| 토큰 | 크기 | 굵기 | 줄 높이 | 사용 위치 |
|---|---:|---:|---:|---|
| `typography.display-xl` | 28px | 800 | 1.25 | 랜딩 페이지 대표 제목 |
| `typography.display-lg` | 24px | 700 | 1.3 | 화면 제목 |
| `typography.display-md` | 20px | 700 | 1.35 | 섹션 제목 |
| `typography.title-md` | 17px | 700 | 1.4 | 선물 카드·창 제목 |
| `typography.title-sm` | 15px | 600 | 1.4 | 카드 소제목 |
| `typography.body-md` | 16px | 400 | 1.5 | 본문·입력창 |
| `typography.body-sm` | 14px | 400 | 1.5 | 보조 정보 |
| `typography.caption` | 12px | 500 | 1.45 | 창 제목 표시줄·부가 정보 |
| `typography.badge` | 12px | 700 | 1.3 | 상태 배지 |
| `typography.button` | 15px | 700 | 1.3 | 버튼 |

### 3.3 타이포그래피 적용 원칙

- 기본 화면 문구는 한국어로 작성한다.
- `.exe`, `you've got mail!` 등의 영문은 장식 문구로만 선택적으로 사용한다.
- 중요한 정보는 12px 미만으로 표시하지 않는다.
- 모바일 입력창의 글씨 크기는 16px 이상으로 유지한다.
- 후원 금액, 선물 가격, 달성률은 쉽게 구분되도록 숫자 가독성을 우선한다.
- 긴 상품명은 카드 높이와 레이아웃을 고려하여 줄바꿈 또는 말줄임 처리한다.
- 오류 메시지는 색상만으로 구분하지 않고 구체적인 문장으로 표시한다.

## 4. 레이아웃

### 4.1 간격 체계

- 기본 단위: **4px**
- 사용 간격: `2 / 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64px`
- 화면 좌우 여백: 모바일 16px, 태블릿 24px, 데스크톱 앱 내부 24px
- 주요 섹션 사이: 24~32px
- 랜딩 페이지 섹션 사이: 48~64px 허용
- 컴포넌트 간격: 8~16px
- 카드 내부 여백: 기본 16px, 큰 카드는 20~24px

### 4.2 웹 브라우저에서도 앱처럼 보이도록 하는 규칙 — 필수

- 전체 화면을 가득 채우는 일반 웹사이트가 아니라 **브라우저 가운데 배치된 모바일 앱 형태의 웹앱**으로 구현한다.
- 데스크톱 기본 앱 영역의 최대 너비는 **430px**이다.
- 앱 외부에는 연보라색 Y2K 데스크톱 배경과 클릭을 방해하지 않는 장식 요소를 배치할 수 있다.
- 앱 컨테이너 기본값:

```css
.app-shell {
  width: min(100%, 430px);
  min-height: 100dvh;
  margin-inline: auto;
}
```

- 화면 너비가 600px 미만이면 앱은 너비 100%를 사용한다.
- 모바일에서는 외곽 장식 프레임과 그림자를 제거한다.
- 데스크톱에서는 앱 외곽에 1~2px 테두리, 약한 입체 그림자, 12~16px 모서리 둥글기를 적용할 수 있다.
- 가짜 스마트폰 테두리나 가짜 주소창을 그리지 않는다.
- 실제 클릭과 입력이 가능한 웹앱 화면이어야 한다.
- 데스크톱 브라우저에서도 동일한 하단 메뉴를 사용할 수 있어야 한다.
- 정보가 많은 생일자 관리 화면에 한해 별도 확장 보기를 제공할 수 있다.
- 확장 보기의 최대 너비는 960px이다.
- 기본 모드는 항상 430px을 유지한다.
- 고정 높이를 강제하지 않고 자연스러운 세로 스크롤을 지원한다.
- `100dvh`와 모바일 안전 영역을 고려한다.

### 4.3 앱 화면의 기본 구조

1. `app-shell`: 화면 중앙에 배치하는 앱 전체 컨테이너.
2. `app-header`: 서비스명, 뒤로 가기, 알림, 프로필 버튼.
3. `screen-content`: 각 화면의 주요 콘텐츠 영역. 하단 메뉴 높이만큼 여백 확보.
4. `bottom-tab-bar`: `홈 / 내 펀딩 / 그룹 / 친구 펀딩 / 마이페이지` 다섯 가지 탭.
5. `retro-window`: 분홍·하늘·보라색 제목 표시줄이 있는 공통 창 형태의 카드.
6. `modal-dialog` 및 `bottom-sheet`: 선택, 확인, 오류 안내에 사용.

**하단 내비게이션 규칙**

- 하단 메뉴는 총 5개로 고정한다.
- 메뉴 순서는 `홈 → 내 펀딩 → 그룹 → 친구 펀딩 → 마이페이지`이다.
- 각 메뉴는 아이콘과 텍스트를 함께 표시한다.
- 활성 메뉴는 핑크색으로 구분한다.
- 모바일 430px 너비에서도 가로 스크롤 없이 표시한다.
- 메뉴별 터치 영역을 충분히 확보한다.
- 생일 캘린더는 별도 하단 메뉴가 아니라 홈에서 접근한다.
- 알림은 상단 헤더의 알림 버튼을 통해서만 접근한다.
- 읽지 않은 알림이 1건 이상이면 알림 아이콘 오른쪽 위에 빨간색 원형 점을 표시한다.
- 읽지 않은 알림이 없으면 빨간색 점을 표시하지 않는다.
- 홈 본문에는 최근 알림 목록을 표시하지 않는다.


**장식 규칙**

- 창 오른쪽의 `□`, `×`, `_` 장식은 실제 기능이 없다면 버튼처럼 오해되지 않도록 처리한다.
- 기능이 없는 장식은 키보드 탐색과 접근성 트리에서 제외한다.

### 4.4 그리드

- 기본 선물 목록은 **1열**로 배치한다.
- 이미지가 충분히 읽히는 경우에만 작은 썸네일을 2열로 배치한다.
- 별도 확장 관리 화면에서는 2열 카드 배치를 허용한다.
- 430px 앱 영역 안에 4~6열 상품 카드를 배치하지 않는다.
- 후원 금액 선택 버튼은 모바일에서 가독성을 유지하도록 배치한다.
- 초대 링크 입력창과 참여 버튼은 세로 방향으로 구성한다.

### 4.5 고정 요소 및 스크롤

- 하단 탭 메뉴는 화면 아래에 고정할 수 있다.
- 화면 콘텐츠에는 하단 메뉴 높이만큼 여백을 확보한다.
- 후원 화면에서 후원하기 버튼을 하단에 고정하는 경우 하단 탭과 겹치지 않도록 한다.
- 모달과 바텀시트는 작은 모바일 화면에서도 스크롤할 수 있어야 한다.
- 입력창에 키보드가 표시되더라도 확인 버튼에 접근할 수 있어야 한다.
- 모바일 안전 영역을 고려한다.

## 5. 그림자와 모서리

### 5.1 레트로 창 그림자

| 토큰 | 값 | 용도 |
|---|---|---|
| `shadow.window` | `3px 3px 0 #77718A` | 기본 창의 입체 그림자 |
| `shadow.window-hover` | `4px 4px 0 #30283C` | 마우스 올림 |

- 클릭 가능한 버튼과 단순 장식 카드를 시각적으로 구분한다.

|---|---:|---|

| `rounded.md` | 10px | 선물 이미지 |
| `rounded.lg` | 14px | 앱 외곽 및 큰 카드 |

## 6. 공통 컴포넌트

> 서비스 기능명세서에 필요한 컴포넌트만 정의한다. 숙소, 예약, 리뷰, 장바구니 등 서비스와 무관한 컴포넌트는 제외한다.

### 6.1 앱 탐색

- **`app-header`**: 약 56px 높이. 로고/서비스명, 필요 시 뒤로 가기, 알림 버튼.
- **`bottom-tab-bar`**: 약 64~72px + 모바일 안전 영역. `홈`, `내 펀딩`, `그룹`, `친구 펀딩`, `마이페이지`의 5개 탭으로 구성한다.
- **`screen-title`**: 화면 제목과 짧은 설명.
- **`retro-window`**: 1~2px 테두리, 파스텔 제목 표시줄, 하트·별 아이콘, 콘텐츠 영역.
- **`notification-button`**: 상단 헤더에서 알림 화면으로 이동하는 아이콘 버튼.
- **`back-button`**: 이전 화면으로 이동하는 버튼.

**탭별 이동**

| 탭 | 이동 화면 | 주요 기능 |
|---|---|---|
| 홈 | 홈 화면 | 생일 D-day, 펀딩 요약, 캘린더 접근 |
| 내 펀딩 | 내 펀딩 화면 | 내가 생성한 펀딩 목록 및 관리 |
| 그룹 | 그룹 화면 | 그룹 생성, 참여 그룹 및 초대 관리 |
| 친구 펀딩 | 친구 펀딩 화면 | 초대 링크 입력, 참여 펀딩 목록, 후원 |
| 마이페이지 | 마이페이지 화면 | 프로필, 생일, 취향 관리 |

### 6.2 버튼·입력·선택

- **`button-primary`**: 핑크 배경, 어두운 글씨, 진한 2px 테두리, 입체 그림자, 높이 44~48px 이상.
- **`button-secondary`**: 흰색 또는 연보라색 배경과 진한 테두리.
- **`button-tertiary`**: 배경 없는 텍스트 버튼.
- **`icon-button`**: 뒤로 가기, 닫기, 알림, 수정 등에 사용. 터치 영역 최소 44×44px.
- **`text-input`**: 이름, 펀딩 이름, 그룹 이름, 초대 링크 입력.
- **`number-input`**: 선물 가격, 후원 금액 입력.
- **`textarea`**: 그룹 설명, 축하 메시지 입력.
- **`select`**: 카테고리 및 옵션 선택.
- **`checkbox`**: 동의 및 선택 상태.
- **`radio`**: 이월 또는 인출 등 단일 선택.
- **`date-picker`**: 생일 및 펀딩 기간 선택.
- **`confirmation-dialog`**: 중요한 행동의 최종 확인.
- **`delete-confirm-dialog`**: 삭제 전용 확인 모달 (2026-10-16 추가). 제목 `정말 삭제하시겠습니까?`, 설명 `삭제한 데이터는 복구할 수 없습니다.`, 버튼 `취소`(보조) · `삭제`(위험). 진행 중에는 닫기 잠금, 성공 시 토스트 `삭제되었습니다.`, 실패 시 모달 안에 오류 표시. 펀딩 삭제(UI-12) · 선물 삭제(UI-10) · 생일 일정 삭제(UI-28)에 사용.
- **`toast` / `inline-alert`**: 성공, 오류, 경고 안내.

**버튼 상태**

- 기본
- 마우스 올림
- 누름
- 비활성
- 로딩
- 성공 또는 완료

**입력 규칙**

- 필수 입력값은 라벨과 함께 표시한다.
- 오류 메시지는 해당 입력창 근처에 표시한다.
- 입력 오류가 발생해도 사용자가 입력한 값은 가능한 한 유지한다.
- 금액 입력창은 숫자 입력에 적합한 모바일 키보드를 사용한다.
- 원화 금액은 천 단위 구분 기호와 `원` 단위를 함께 표시한다.

### 6.3 선물 등록과 AI 추천

- **`gift-form`**: 선물 이름, 원 단위 정수 가격, 상품 링크, 이미지 업로드, 등록/취소 버튼.
- **`gift-image-uploader`**: 파일 선택, 미리보기, 변경, 삭제, 형식·크기 안내.
- **`gift-card`**: 선물 이미지, 이름, 실제 가격, 목표 달성률, 진행률 바, 상태, 후원 버튼.
- **`gift-list`**: 선물 카드 목록.
- **`preference-form`**: AI 추천에 사용할 관심사, 카테고리, 가격대.
- **`ai-recommendation-card`**: 추천 선물, 추천 이유, 예상 가격, `선물로 등록` 버튼.
- **`loading-skeleton`**: 추천 결과 또는 카드 로딩 중 표시하는 임시 형태.

**선물 등록 규칙**

- 선물은 최소 1개 이상 등록해야 한다.
- 선물 이름, 실제 가격, 이미지, 상품 URL은 필수이다.
- 선물 가격은 목표 금액으로 사용한다.
- 여러 선물을 등록해도 각 선물의 목표 금액은 독립적으로 관리한다.
- AI 추천 결과는 참고용이며 실제 판매 가격과 URL은 생일자가 확인한다.

**후원자용 선물 카드**

- 선물 이미지
- 선물 이름
- 실제 가격 및 목표 금액
- 상품 구매 URL
- 목표 달성률(%)
- 진행률 바
- 후원 상태
- `후원하기` 버튼

**생일자용 선물 카드**

- 후원자용 카드의 기본 정보
- 실제 전체 모금액
- 남은 모금액
- 후원자별 내역 확인 버튼

### 6.4 그룹과 펀딩 생성

- **`group-card`**: 그룹명, 참여 정보, 연결된 펀딩, 그룹 열기 버튼.
- **`group-create-form`**: 그룹 이름, 선택적 설명, 생성 버튼.
- **`invite-link-panel`**: 초대 링크, 링크 복사, 링크 상태, 비활성화 버튼.
- **`member-list`**: 그룹 참여자 목록.
- **`funding-form`**: 펀딩 이름, 그룹 선택, 시작일·종료일, 선물 1개 이상.
- **`date-range-picker`**: 펀딩 기간 선택.
- **`funding-status-badge`**: `예정`, `진행 중`, `종료`.
- **`funding-summary-card`**: 펀딩 개요, 선물별 진행 상태, 상세 화면 이동.

**그룹 관리 규칙**

- 그룹 이름과 펀딩 이름은 별도로 관리한다.
- 그룹 생성자는 기본 관리자가 된다.
- 그룹 관리자는 초대 링크를 생성, 복사, 비활성화할 수 있다.
- 그룹 참여 권한과 개별 펀딩 참여 권한을 구분한다.
- 권한이 없는 사용자는 비공개 그룹과 펀딩을 열람할 수 없다.

### 6.5 친구 펀딩 참여 및 관리

- **`friend-funding-list`**: 참여한 친구 펀딩 목록. 진행 중과 종료 상태를 구분한다.
- **`friend-funding-card`**: 펀딩 이름, 생일자, 그룹, 펀딩 기간, 상태, 달성률 및 진행률 바.
- **`join-funding-button`**: `+ 친구 펀딩 참여하기` 버튼.
- **`invite-link-input-dialog`**: 초대 링크 입력창과 `링크 확인` 버튼.
- **`funding-join-confirmation`**: 참여 대상 정보와 `참여하기` 버튼.
- **`friend-funding-detail`**: 선물 목록, 달성률, 후원 버튼, 본인 후원 내역.
- **`friend-funding-empty-state`**: 참여한 펀딩이 없을 때 안내와 참여 버튼.
- **`invite-error-alert`**: 유효하지 않거나 비활성화된 초대 링크 오류 안내.

**참여 흐름**

1. `친구 펀딩` 화면에 접속한다.
2. `+ 친구 펀딩 참여하기` 버튼을 클릭한다.
3. 초대 링크 입력 모달을 연다.
4. 링크를 입력하고 `링크 확인` 버튼을 클릭한다.
5. 링크 유효성 및 접근 권한을 검증한다.
6. 펀딩 이름, 생일자 이름, 그룹 이름을 표시한다.
7. `참여하기` 버튼으로 최종 참여를 확정한다.
8. 참여 완료 후 펀딩 상세 화면으로 이동한다.
9. 친구 펀딩 목록에 해당 펀딩을 추가한다.

**예외 처리**

- 유효하지 않은 링크: 오류 안내
- 비활성화된 링크: 참여 불가 안내
- 로그인하지 않은 사용자: 로그인 후 참여 과정 계속 진행
- 이미 참여한 펀딩: 중복 추가하지 않고 기존 상세 화면으로 이동
- 권한이 없는 펀딩: 접근 차단
- 참여한 펀딩 없음: 빈 상태 안내와 참여 버튼 표시

**정보 표시 규칙**

- 친구 펀딩 목록과 상세 화면에는 실제 전체 모금액과 남은 모금액을 표시하지 않는다.
- 선물 가격과 목표 달성률은 표시한다.
- 다른 후원자의 개별 후원 금액 및 내역은 표시하지 않는다.
- 종료된 펀딩은 조회 가능하지만 추가 후원은 불가능하다.

### 6.6 후원과 달성률

- **`funding-progress`**: 0~100% 진행률 바와 숫자.
- **`donation-amount-form`**: 선택한 선물, 추천 금액 버튼, 직접 입력창, 후원 금액 검증.
- **`donation-preset-button`**: 5,000원, 10,000원, 30,000원 추천 금액 버튼.
- **`donation-message-card`**: 후원 금액 입력 화면 안에 배치하는 선택형 축하 메시지 카드.
- **`donation-submit-button`**: 선택한 금액에 따라 문구가 변경되는 후원 버튼.
- **`donation-limit-alert`**: 초과 후원 시 최대 후원 가능 금액 안내.
- **`donation-success`**: 후원 성공 후 자동 이동하는 완료 화면.
- **`my-contributions-list`**: 로그인한 사용자의 본인 후원 내역.
- **`recipient-contribution-table`**: 생일자 전용 실제 모금액 및 후원자별 내역.
- **`goal-achieved-state`**: 목표 달성 상태와 후원 버튼 비활성화.

**후원 금액 선택**

- 추천 금액은 `5,000원 / 10,000원 / 30,000원`이다.
- 직접 입력으로 원하는 금액을 설정할 수 있다.
- 후원 금액은 0원보다 큰 정수여야 한다.
- 금액 선택에 따라 후원 버튼 문구를 변경한다.
- 예: `20,000원 후원하기`

**후원 처리**

1. 선물을 선택한다.
2. 추천 금액을 선택하거나 직접 입력한다.
3. 같은 화면에서 축하 메시지를 작성할 수 있다.
4. `후원하기` 버튼을 클릭한다.
5. 서버에서 후원 가능 여부를 검증한다.
6. 성공 시 후원 완료 화면으로 자동 이동한다.
7. 실패 시 기존 입력값과 메시지를 유지한다.

**초과 후원 처리**

- 후원 금액이 남은 모금액보다 크면 후원을 진행하지 않는다.
- 정확한 최대 후원 가능 금액을 안내한다.
- 안내 문구:

`현재 이 선물에는 최대 {후원 가능 금액}원까지 후원할 수 있습니다. 후원 금액을 수정해 주세요.`

- 남은 금액이 0원이면 `후원이 마감된 선물입니다.`를 표시한다.
- 일반 화면에서는 실제 전체 모금액과 남은 모금액을 표시하지 않는다.
- 다른 사용자의 후원으로 금액이 변경된 경우 최신 상태를 기준으로 다시 검증한다.

**중복 처리**

- 후원 처리 중에는 버튼을 비활성화한다.
- 동일 요청의 중복 처리를 방지한다.
- 사용자가 새로운 후원 요청으로 같은 선물에 다시 후원하는 것은 허용한다.
- 동시 후원으로 목표 금액을 초과하지 않도록 서버에서 처리한다.

**후원 완료 화면**

- 후원 완료 안내
- 후원한 선물 이름
- 본인이 후원한 금액
- `친구 펀딩으로 돌아가기` 버튼
- `내 후원 내역 보기` 버튼

- 후원 성공 시 자동으로 완료 화면으로 이동한다.
- 후원 완료 후 별도의 축하 메시지 작성 화면으로 이동하지 않는다.

### 6.7 펀딩 종료·이월·정산

- **`shortfall-choice-card`**: 생일자 전용 목표 미달 처리 카드.
- **`shortfall-confirmation-dialog`**: 선택한 처리 방식과 결과를 다시 확인하는 모달.
- **`carryover-history`**: 이월 금액, 원래 선물, 다음 생일 적용 상태.
- **`settlement-card`**: 생일자 전용 정산 가능 금액, 정산 요청, 처리 상태, 이력.
- **`settlement-status-badge`**: `요청`, `처리 중`, `완료`, `실패`.

**목표 미달 처리 선택지**

1. `다음 생일로 이월`
2. `현재 모금액 인출`

- 두 가지 중 하나만 선택할 수 있다.
- 동일 금액을 이월과 인출에 중복 사용할 수 없다.
- 정산은 생일자만 요청할 수 있다.
- 실제 송금이 구현되지 않은 경우 `모의 정산`을 표시한다.
- `본인 부담금 추가` 버튼은 제공하지 않는다.
- 이월 금액의 다음 생일 적용 방식은 별도 정책으로 확정한다.

### 6.8 축하 메시지·생일·알림

- **`private-message-form`**: 후원 금액 입력 화면 안에 배치하는 선택형 축하 메시지 카드.
- **`message-template-button`**: 추천 축하 문구 선택 버튼.
- **`message-textarea`**: 축하 메시지 직접 입력 및 수정.
- **`recipient-message-inbox`**: 생일자 전용 축하 편지함.
- **`birthday-calendar`**: 월별 생일 달력과 일정.
- **`birthday-event-form`**: 친구 이름과 생일 등록, 수정, 삭제.
- **`notification-list`**: 생일 하루 전·당일 알림, 읽음 상태, 연결 화면 이동.

**추천 축하 문구**

- `생일 축하해! 🎂`
- `태어나줘서 고마워 💗`
- `오늘 하루 행복하게 보내! 🎉`
- `항상 좋은 일만 가득하길 ✨`

**축하 메시지 규칙**

- 메시지는 후원 금액 입력 화면에서 작성한다.
- 메시지 작성은 선택사항이다.
- 추천 문구를 선택하면 입력창에 자동 입력한다.
- 자동 입력된 문구는 수정하거나 삭제할 수 있다.
- 메시지 없이도 후원할 수 있다.
- 후원 성공 시 메시지를 함께 저장한다.
- 후원 실패 시 메시지만 저장되지 않도록 한다.
- 작성자는 실제 계정 이름으로 기록한다.
- 생일자만 메시지를 확인할 수 있다.
- 메시지에 후원 금액을 자동 표시하지 않는다.
- 다른 후원자에게 메시지 내용과 작성자를 공개하지 않는다.

**생일 캘린더**

- 홈에서 생일 캘린더로 이동한다.
- 사용자가 친구의 생일을 직접 등록, 수정, 삭제할 수 있다.
- 직접 등록한 생일은 개인 캘린더 일정으로 관리한다.
- 다른 회원의 프로필 생일 정보를 변경하지 않는다.
- 접근 가능한 펀딩만 생일 일정에 연결할 수 있다.

**알림**

- 생일 하루 전 알림
- 생일 당일 알림
- 읽음/안 읽음 상태
- 관련 생일 또는 펀딩 화면 이동
- 동일 일정 중복 알림 방지

### 6.9 공통 화면 상태

- **`empty-state`**: 데이터가 없을 때 안내와 다음 행동 버튼.
- **`loading-state`**: 스켈레톤 또는 로딩 표시.
- **`error-state`**: 오류 내용과 재시도 버튼.
- **`access-denied-state`**: 권한이 없는 사용자의 접근 차단 안내.
- **`offline-or-network-error`**: 네트워크 오류 시 재시도 안내.
- **`success-state`**: 작업 성공 안내.
- **`disabled-state`**: 수행할 수 없는 작업의 비활성 상태.

**공통 예외 처리 원칙**

- 오류 발생 시 가능한 한 입력값을 유지한다.
- 오류 문구는 사용자가 다음 행동을 알 수 있도록 작성한다.
- 로딩 중에는 동일 요청을 중복 전송하지 않는다.
- 권한이 없는 데이터는 화면뿐 아니라 서버 응답에서도 제외한다.
- 후원 및 정산과 관련된 요청은 중복 처리되지 않도록 한다.

## 8. 반응형 디자인

| 구분 | 화면 너비 | 동작 방식 |
|---|---|---|
| 작은 모바일 | 375px 미만 | 전체 너비 사용, 좌우 여백 12~16px, 1열 배치 |
| 모바일 | 375~599px | 전체 너비 앱, 외곽 프레임 없음, 하단 5개 탭 |
| 웹 브라우저 앱 보기 | 600px 이상 | 최대 430px 앱을 가운데 배치, 바깥에 Y2K 배경 |
| 선택적 확장 관리 화면 | 1024px 이상 | 생일자 관리 화면에 한해 최대 960px |

### 8.1 접근성과 인터랙션

- 터치 대상은 가능한 한 최소 44×44px을 확보한다.
- 하단 5개 탭은 모바일에서도 가로 스크롤 없이 표시한다.
- 키보드 포커스를 명확하게 표시한다.
- Tab 이동 순서를 화면 읽기 순서에 맞춘다.
- 모달은 `Esc`로 닫을 수 있도록 한다.
- 버튼과 입력창에는 의미 있는 이름과 라벨을 제공한다.
- 장식 아이콘은 접근성 탐색에서 제외한다.
- 진행률에는 숫자 텍스트와 접근성 속성을 제공한다.
- 애니메이션은 100~180ms 정도로 짧게 적용한다.
- `prefers-reduced-motion` 설정을 존중한다.
- 자동 재생 음악과 빠르게 깜빡이는 효과는 사용하지 않는다.
- WCAG AA 수준의 텍스트 대비를 목표로 한다.
- 대비가 부족한 색상은 실제 구현 시 조정한다.
- 하단 메뉴가 입력창, 확인 버튼, 오류 메시지를 가리지 않도록 한다.
- CD·별·나비·스티커 등 장식 요소가 클릭과 스크롤을 방해하지 않도록 한다.

### 8.2 후원 화면 반응형 규칙

- 선물 정보는 세로로 배치한다.
- 추천 후원 금액 버튼은 모바일 너비에 맞게 배치한다.
- 직접 입력창은 충분한 너비를 확보한다.
- 축하 메시지 카드는 금액 입력 영역 아래에 배치한다.
- 후원하기 버튼은 금액과 메시지 입력 이후에 표시한다.
- 작은 화면에서도 메시지 입력창과 버튼이 잘리지 않도록 한다.
- 후원 처리 중 로딩 상태를 명확하게 표시한다.
- 초과 후원 오류는 금액 입력창 근처에 표시한다.

### 8.3 친구 펀딩 화면 반응형 규칙

- 친구 펀딩 목록은 기본 1열 카드로 표시한다.
- 초대 링크 입력 모달은 모바일 화면 너비를 초과하지 않는다.
- 링크 입력창은 긴 URL을 입력할 수 있도록 구성한다.
- 참여 대상 정보는 이름과 그룹을 구분하여 표시한다.
- 참여하기 버튼은 확인 정보 아래에 배치한다.
- 펀딩 카드에는 실제 전체 모금액과 남은 모금액을 표시하지 않는다.

## 9. 미확정 사항

### 9.1 참고 이미지의 한계

- Pinterest 이미지로는 정확한 색상 코드, 원본 CSS, 폰트 파일 및 구현 수치를 알 수 없다.
- 본 문서의 색상과 수치는 참고 이미지를 바탕으로 정한 프로젝트 디자인 기준값이다.
- 참고 이미지의 음악 플레이어, 쇼핑 장바구니, 가짜 운영체제 작업 표시줄, 커뮤니티 사진 모음은 서비스 기능과 무관하여 제외한다.

### 9.2 서비스 정책 미확정

- 실제 결제 수단과 정산 방식
- 실제 후원금 보관 및 이월 관련 정책
- 후원 취소 및 환불 정책
- 다음 생일로 이월된 금액을 어떤 선물에 적용할지
- 그룹 탈퇴 및 초대 링크 만료 정책
- 앱 내부 알림 이외의 알림 전송 방식
- 실제 은행 송금 및 본인 명의 계좌 인증 방식

### 9.3 디자인 구현 시 확인 사항

- 실제 모바일 기기에서 5개 하단 탭의 가독성
- 430px 앱 영역에서 긴 펀딩 이름 및 상품명 표시
- 초대 링크 입력 모달의 작은 화면 대응
- 금액 입력 시 모바일 키보드와 버튼 겹침 여부
- 축하 메시지 카드의 입력 길이 및 스크롤 처리
- 실제 색상 대비 및 접근성 검사

## 11. 관련 문서 및 관리 원칙

| 문서 | 역할 |
|---|---|
| `DEFINITION.md` | 제품 정체성, 핵심 가치, 차별성 및 MVP 범위 |
| `feature_spec.md` | 상세 기능, 입력값, 처리 규칙 및 예외 처리 |
| `screen.md` | 화면 목록, 화면 이동, 권한별 표시 |
| `TechStack.md` | 기술 스택, 시스템 아키텍처 및 테스트 |
| `유저시나리오.md` | 사용자 역할별 서비스 이용 흐름 |
| `base.md` | 컬러, 폰트, 컴포넌트, 레이아웃 및 디자인 시스템 |
| 페이지별 화면명세서 | 화면별 UI 배치, 버튼, 입력 및 상태 |

**문서 관리 원칙**

- 이 파일은 서비스 전체의 시각적 디자인 기준을 정의한다.
- 기능별 상세 규칙은 `feature_spec.md`를 따른다.
- 화면 이름과 버튼 동작은 `screen.md`를 따른다.
- 사용자 이용 흐름은 `유저시나리오.md`를 따른다.
- 기술 선정 및 구현 환경은 `TechStack.md`를 따른다.
- 화면별 세부 배치는 개별 화면명세서에서 정의한다.
- 기능 변경 시 관련 디자인 컴포넌트도 함께 갱신한다.
- 모든 화면에서 컬러, 폰트, 간격, 버튼 및 상태 표시의 일관성을 유지한다.
