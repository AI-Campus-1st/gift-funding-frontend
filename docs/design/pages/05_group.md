### UI-06 그룹 화면명세서

### 1. 화면 개요

- **화면 ID:** UI-06
- **화면 이름:** 그룹
- **화면 목적:** 내가 만들거나 참여한 비공개 그룹을 조회한다.
- **접근 권한:** 로그인 사용자(조회·관리 권한은 그룹/펀딩별로 구분)
- **관련 기능 ID:** F-05, F-06
- **파일명:** `06_group.md`
- **화면 경로:** `/group` (제안 경로, 구현 시 확정)

#### 1.1 기본 정책

- 사용자 및 펀딩별 접근 권한을 서버에서 검증한다.
- 홈에는 그룹 요약을 표시하지 않으며 그룹은 하단 그룹 탭에서만 접근한다.
- 서비스 공통 디자인은 `base.md`를 따른다.

---

### 2. 화면 구성 및 배치

#### 2.1 상단 영역

**표시 요소**
- 레트로 창 스타일의 상단 헤더
- 화면 제목: `그룹`
- 이전 화면으로 이동하는 뒤로 가기 버튼(주요 탭 화면에서는 생략 가능)

**배치 위치**
- 상단 헤더는 화면 최상단에 배치한다.
- 제목은 헤더 중앙 또는 콘텐츠 시작점에 맞춘다.
- 화면 전환 중에는 중복 요청을 방지한다.

#### 2.2 중앙 영역

**표시 요소**
- 그룹 이름
- 설명
- 참여자 수
- 연결된 펀딩

**컴포넌트 배치**
- 정보와 입력 요소를 세로 방향으로 배치한다.
- 데이터 목록은 카드 또는 항목 단위로 구분한다.
- 접근 권한이 없는 정보는 렌더링하지 않는다.
- 데이터가 없으면 빈 상태 안내와 관련 행동 버튼을 표시한다.

#### 2.3 하단 영역

**표시 요소**
- 주요 행동 버튼 또는 화면 내 이동 링크
- 하단 5개 탭(홈 / 내 펀딩 / 그룹 / 친구 펀딩 / 마이페이지)을 제공한다.

---

### 3. UI 컴포넌트 상세

| 컴포넌트 / 버튼 | UI 형태 | 클릭 또는 입력 시 동작 | 이동 대상 |
|---|---|---|---|
| 그룹 만들기 | 버튼/카드/입력 컨트롤 | 그룹 만들기 실행, 필요한 입력과 권한 확인 | UI-14 |
| 그룹 카드 | 버튼/카드/입력 컨트롤 | 그룹 카드 실행, 필요한 입력과 권한 확인 | UI-15 |

#### 3.1 데이터 표시 규칙

- 기본 표시 데이터: 그룹 이름, 설명, 참여자 수, 연결된 펀딩.
- 생성자에게만 허용된 정보는 후원자에게 노출하지 않는다.
- 날짜는 사용자에게 이해하기 쉬운 형식으로 표시하고 금액에는 천 단위 구분 기호를 사용한다.
- 서버 응답을 기준으로 상태를 갱신하며 클라이언트 표시만으로 권한을 판단하지 않는다.

---

### 4. 사용자 동작 및 처리 흐름

1. 사용자가 `그룹` 화면에 진입한다.
2. 로그인 상태와 접근 권한을 확인한다.
3. 필요한 데이터를 요청하고 로딩 상태를 표시한다.
4. 정상 응답이면 화면의 카드, 입력값, 상태를 표시한다.
5. 사용자가 버튼 또는 항목을 선택하면 유효성 및 권한을 확인한다.
6. 요청 성공 시 갱신된 결과를 보여주거나 관련 화면으로 이동한다.
7. 요청 실패 시 기존 데이터를 임의로 변경하지 않고 오류를 안내한다.

#### 4.1 주요 화면 이동

- `그룹 만들기` → UI-14
- `그룹 카드` → UI-15

---

### 5. 입력값 검증 및 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 로그인하지 않음 | 로그인 화면(UI-03)으로 이동, 필요한 경우 복귀 경로 보존 |
| 접근 권한 없음 | 비공개 데이터 숨김, 접근 불가 안내 |
| 데이터 없음 | 빈 상태 문구 및 가능한 다음 행동 표시 |
| 로딩 중 | 로딩 표시 및 중복 제출 방지 |
| 네트워크/API 오류 | 오류 메시지와 재시도 동작 제공 |
| 이미 종료/완료된 작업 | 변경 및 후원 불가 상태 표시 |

---

### 6. 화면 상태 정의

- **초기 상태:** 사용자 및 대상 데이터 확인 전.
- **로딩 상태:** 데이터 조회 또는 요청 처리 중.
- **정상 상태:** 권한이 허용된 데이터를 표시.
- **빈 상태:** 표시할 항목이 없는 경우.
- **오류 상태:** 입력 검증 실패, 네트워크 오류, 접근 제한.
- **완료 상태:** 작업이 성공한 경우 결과 반영 또는 다음 화면으로 이동.

---

### 7. 디자인 적용 기준

- 모바일 우선 반응형 웹으로 구성한다.
- 데스크톱에서는 최대 430px 앱 영역을 중앙 배치한다.
- `base.md`의 Y2K 핑크 레트로 + Windows 98 스타일을 따른다.
- 주요 CTA는 브랜드 핑크 `#EF78BD`를 사용한다.
- 앱 배경은 `#FFFDFD`, 외부 배경은 `#F8F1FA`를 사용한다.
- 폰트·테두리·입력창·카드·상태 배지는 `base.md` 공통 규칙을 재사용한다.
- 실제 결제/정산이 아닌 시뮬레이션이면 `모의 후원` 또는 `모의 정산`을 명시한다.

---

### 8. 개발 및 테스트 확인 사항

- [ ] 인증 및 접근 권한을 서버에서 검증한다.
- [ ] 빈 목록, 로딩, 실패, 완료 상태를 구현한다.
- [ ] 모바일 및 데스크톱 반응형 레이아웃을 확인한다.
- [ ] 화면 전환 후 데이터와 상태가 일관되게 유지된다.
- [ ] 개인 후원 정보 비공개 정책을 검증한다.
- [ ] API 오류 시 중복 처리나 잘못된 완료 안내가 발생하지 않는다.

> **문서 기준:** `DEFINITION(1).md`, `FEATURE_SPEC(1).md`, `screen(1).md`, `UserScenario.md`, `base.md`. 화면 ID UI-09~UI-29는 상세 명세서 분리를 위해 새로 배정한 번호이다. URL 및 세부 인터랙션은 구현 제안으로 최종 확정이 필요하다.

- 화면 전환 중에는 중복 요청을 방지한다.

#### 2.2 중앙 영역

**표시 요소**
- 그룹 이름
- 설명
- 참여자
- 연결된 펀딩

**컴포넌트 배치**

- 접근 권한이 없는 정보는 렌더링하지 않는다.
- 데이터가 없으면 빈 상태 안내와 관련 행동 버튼을 표시한다.

#### 2.3 하단 영역

**표시 요소**
- 주요 행동 버튼 또는 화면 내 이동 링크
- 세부 화면은 상단 뒤로 가기를 제공하며 하단 탭은 필요에 따라 숨긴다.
