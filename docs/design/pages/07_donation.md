### UI-19 선물 후원 및 축하 메시지 작성 화면명세서

### 1. 화면 개요

- **화면 ID:** UI-19
- **화면 이름:** 선물 후원 및 축하 메시지 작성
- **화면 목적:** 선택한 선물에 원하는 금액을 후원하며 축하 메시지를 선택적으로 작성한다.
- **접근 권한:** 로그인 사용자(조회·관리 권한은 그룹/펀딩별로 구분)
- **관련 기능 ID:** F-08, F-10, F-14
- **파일명:** `19_donation.md`
- **화면 경로:** `/donation` (제안 경로, 구현 시 확정)

#### 1.1 기본 정책

- 후원자 화면에서는 실제 전체 모금액·남은 모금액·다른 후원자의 개별 후원 금액을 표시하지 않는다.
- 목표액 초과 후원은 거부하고 이때만 정확한 최대 후원 가능 금액을 안내한다. 동일 요청 중복 처리는 방지하되 의도적인 반복 후원은 허용한다. 축하 메시지는 선택이며 계정 이름으로 기록한다.
- 서비스 공통 디자인은 `base.md`를 따른다.

---

### 2. 화면 구성 및 배치

#### 2.1 상단 영역

**표시 요소**
- 레트로 창 스타일의 상단 헤더
- 화면 제목: `선물 후원 및 축하 메시지 작성`
- 이전 화면으로 이동하는 뒤로 가기 버튼(주요 탭 화면에서는 생략 가능)

**배치 위치**
- 상단 헤더는 화면 최상단에 배치한다.
- 제목은 헤더 중앙 또는 콘텐츠 시작점에 맞춘다.
- 화면 전환 중에는 중복 요청을 방지한다.

#### 2.2 중앙 영역

**표시 요소**
- 선물 이름
- 목표 가격
- 추천 금액
- 직접 입력 금액
- 축하 메시지(선택)

**컴포넌트 배치**
- 정보와 입력 요소를 세로 방향으로 배치한다.
- 데이터 목록은 카드 또는 항목 단위로 구분한다.
- 접근 권한이 없는 정보는 렌더링하지 않는다.
- 데이터가 없으면 빈 상태 안내와 관련 행동 버튼을 표시한다.

#### 2.3 하단 영역

**표시 요소**
- 주요 행동 버튼 또는 화면 내 이동 링크
- 세부 화면은 상단 뒤로 가기를 제공하며 하단 탭은 필요에 따라 숨긴다.

---

### 3. UI 컴포넌트 상세

| 컴포넌트 / 버튼 | UI 형태 | 클릭 또는 입력 시 동작 | 이동 대상 |
|---|---|---|---|
| 추천 금액 선택 | 버튼/카드/입력 컨트롤 | 추천 금액 선택 실행, 필요한 입력과 권한 확인 | UI-19 |
| 후원하기 | 버튼/카드/입력 컨트롤 | 후원하기 실행, 필요한 입력과 권한 확인 | UI-20 |
| 취소 | 버튼/카드/입력 컨트롤 | 취소 실행, 필요한 입력과 권한 확인 | UI-18 |

#### 3.1 데이터 표시 규칙

- 기본 표시 데이터: 선물 이름, 목표 가격, 추천 금액, 직접 입력 금액, 축하 메시지(선택).
- 생성자에게만 허용된 정보는 후원자에게 노출하지 않는다.
- 날짜는 사용자에게 이해하기 쉬운 형식으로 표시하고 금액에는 천 단위 구분 기호를 사용한다.
- 서버 응답을 기준으로 상태를 갱신하며 클라이언트 표시만으로 권한을 판단하지 않는다.

---

### 4. 사용자 동작 및 처리 흐름

1. 사용자가 `선물 후원 및 축하 메시지 작성` 화면에 진입한다.
2. 로그인 상태와 접근 권한을 확인한다.
3. 필요한 데이터를 요청하고 로딩 상태를 표시한다.
4. 정상 응답이면 화면의 카드, 입력값, 상태를 표시한다.
5. 사용자가 버튼 또는 항목을 선택하면 유효성 및 권한을 확인한다.
6. 요청 성공 시 갱신된 결과를 보여주거나 관련 화면으로 이동한다.
7. 요청 실패 시 기존 데이터를 임의로 변경하지 않고 오류를 안내한다.

#### 4.1 주요 화면 이동

- `추천 금액 선택` → UI-19
- `후원하기` → UI-20
- `취소` → UI-18

---

### 5. 입력값 검증 및 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 로그인하지 않음 | 로그인 화면(UI-03)으로 이동, 필요한 경우 복귀 경로 보존 |
| 접근 권한 없음 | 비공개 데이터 숨김, 접근 불가 안내 |
| 데이터 없음 | 빈 상태 문구 및 가능한 다음 행동 표시 |
| 로딩 중 | 로딩 표시 및 중복 제출 방지 |
| 네트워크/API 오류 | 오류 메시지와 재시도 동작 제공 |
| 이미 종료/완료된 작업 | 변경 및 후원 불가 상태 표시 |

---

### 6. 화면 상태 정의

- **초기 상태:** 사용자 및 대상 데이터 확인 전.
- **로딩 상태:** 데이터 조회 또는 요청 처리 중.
- **정상 상태:** 권한이 허용된 데이터를 표시.
- **빈 상태:** 표시할 항목이 없는 경우.
- **오류 상태:** 입력 검증 실패, 네트워크 오류, 접근 제한.
- **완료 상태:** 작업이 성공한 경우 결과 반영 또는 다음 화면으로 이동.

---

### 7. 디자인 적용 기준

- 모바일 우선 반응형 웹으로 구성한다.
- 데스크톱에서는 최대 430px 앱 영역을 중앙 배치한다.
- `base.md`의 Y2K 핑크 레트로 + Windows 98 스타일을 따른다.
- 주요 CTA는 브랜드 핑크 `#EF78BD`를 사용한다.
- 앱 배경은 `#FFFDFD`, 외부 배경은 `#F8F1FA`를 사용한다.
- 폰트·테두리·입력창·카드·상태 배지는 `base.md` 공통 규칙을 재사용한다.
- 실제 결제/정산이 아닌 시뮬레이션이면 `모의 후원` 또는 `모의 정산`을 명시한다.

---

### 8. 개발 및 테스트 확인 사항

- [ ] 인증 및 접근 권한을 서버에서 검증한다.
- [ ] 빈 목록, 로딩, 실패, 완료 상태를 구현한다.
- [ ] 모바일 및 데스크톱 반응형 레이아웃을 확인한다.
- [ ] 화면 전환 후 데이터와 상태가 일관되게 유지된다.
- [ ] 개인 후원 정보 비공개 정책을 검증한다.
- [ ] API 오류 시 중복 처리나 잘못된 완료 안내가 발생하지 않는다.

### UI-21 내 후원 내역 화면명세서

### 1. 화면 개요

- **화면 ID:** UI-21
- **화면 이름:** 내 후원 내역
- **화면 목적:** 사용자가 자신이 참여한 후원 이력을 조회한다.
- **접근 권한:** 로그인 사용자(조회·관리 권한은 그룹/펀딩별로 구분)
- **관련 기능 ID:** F-08, F-13
- **파일명:** `21_my_donations.md`
- **화면 경로:** `/my-donations` (제안 경로, 구현 시 확정)

#### 1.1 기본 정책

- 후원자 화면에서는 실제 전체 모금액·남은 모금액·다른 후원자의 개별 후원 금액을 표시하지 않는다.
- 권한이 없는 기능과 정보는 표시하지 않고 API에서도 접근을 차단한다.
- 서비스 공통 디자인은 `base.md`를 따른다.

---

### 2. 화면 구성 및 배치

#### 2.1 상단 영역

**표시 요소**
- 레트로 창 스타일의 상단 헤더
- 화면 제목: `내 후원 내역`
- 이전 화면으로 이동하는 뒤로 가기 버튼(주요 탭 화면에서는 생략 가능)

**배치 위치**
- 상단 헤더는 화면 최상단에 배치한다.
- 제목은 헤더 중앙 또는 콘텐츠 시작점에 맞춘다.
- 화면 전환 중에는 중복 요청을 방지한다.

#### 2.2 중앙 영역

**표시 요소**
- 후원 대상
- 선물 이름
- 본인 후원 금액
- 후원 일시
- 처리 상태

**컴포넌트 배치**
- 정보와 입력 요소를 세로 방향으로 배치한다.
- 데이터 목록은 카드 또는 항목 단위로 구분한다.
- 접근 권한이 없는 정보는 렌더링하지 않는다.
- 데이터가 없으면 빈 상태 안내와 관련 행동 버튼을 표시한다.

#### 2.3 하단 영역

**표시 요소**
- 주요 행동 버튼 또는 화면 내 이동 링크
- 세부 화면은 상단 뒤로 가기를 제공하며 하단 탭은 필요에 따라 숨긴다.

---

### 3. UI 컴포넌트 상세

| 컴포넌트 / 버튼 | UI 형태 | 클릭 또는 입력 시 동작 | 이동 대상 |
|---|---|---|---|
| 친구 펀딩 상세 | 버튼/카드/입력 컨트롤 | 친구 펀딩 상세 실행, 필요한 입력과 권한 확인 | UI-18 |
| 뒤로 가기 | 버튼/카드/입력 컨트롤 | 뒤로 가기 실행, 필요한 입력과 권한 확인 | UI-07 |

#### 3.1 데이터 표시 규칙

- 기본 표시 데이터: 후원 대상, 선물 이름, 본인 후원 금액, 후원 일시, 처리 상태.
- 생성자에게만 허용된 정보는 후원자에게 노출하지 않는다.
- 날짜는 사용자에게 이해하기 쉬운 형식으로 표시하고 금액에는 천 단위 구분 기호를 사용한다.
- 서버 응답을 기준으로 상태를 갱신하며 클라이언트 표시만으로 권한을 판단하지 않는다.

---

### 4. 사용자 동작 및 처리 흐름

1. 사용자가 `내 후원 내역` 화면에 진입한다.
2. 로그인 상태와 접근 권한을 확인한다.
3. 필요한 데이터를 요청하고 로딩 상태를 표시한다.
4. 정상 응답이면 화면의 카드, 입력값, 상태를 표시한다.
5. 사용자가 버튼 또는 항목을 선택하면 유효성 및 권한을 확인한다.
6. 요청 성공 시 갱신된 결과를 보여주거나 관련 화면으로 이동한다.
7. 요청 실패 시 기존 데이터를 임의로 변경하지 않고 오류를 안내한다.

#### 4.1 주요 화면 이동

- `친구 펀딩 상세` → UI-18
- `뒤로 가기` → UI-07

---

### 5. 입력값 검증 및 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 로그인하지 않음 | 로그인 화면(UI-03)으로 이동, 필요한 경우 복귀 경로 보존 |
| 접근 권한 없음 | 비공개 데이터 숨김, 접근 불가 안내 |
| 데이터 없음 | 빈 상태 문구 및 가능한 다음 행동 표시 |
| 로딩 중 | 로딩 표시 및 중복 제출 방지 |
| 네트워크/API 오류 | 오류 메시지와 재시도 동작 제공 |
| 이미 종료/완료된 작업 | 변경 및 후원 불가 상태 표시 |

### 6. 화면 상태 정의

- **초기 상태:** 사용자 및 대상 데이터 확인 전.
- **로딩 상태:** 데이터 조회 또는 요청 처리 중.
- **정상 상태:** 권한이 허용된 데이터를 표시.
- **빈 상태:** 표시할 항목이 없는 경우.
- **오류 상태:** 입력 검증 실패, 네트워크 오류, 접근 제한.
- **완료 상태:** 작업이 성공한 경우 결과 반영 또는 다음 화면으로 이동.
