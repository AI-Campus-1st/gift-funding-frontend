### UI-01 랜딩 페이지 화면명세서

### 1. 화면 개요

| 항목 | 내용 |
|---|---|
| 화면 ID | UI-01 |
| 화면 이름 | 랜딩 페이지 |
| 파일명 | 01_landing.md |
| 화면 목적 | 처음 방문한 사용자에게 서비스를 소개하고 회원가입 또는 로그인을 유도 |
| 접근 권한 | 비회원 및 회원 |
| 진입 경로 | 서비스 기본 URL |
| 관련 화면 | UI-02 회원가입, UI-03 로그인, UI-04 홈 |
| 적용 디자인 | design.md |

#### 1.1 화면 목적

서비스를 처음 방문한 사용자가 다음 내용을 쉽게 이해하도록 한다.

1. 원하는 생일선물을 등록할 수 있다.
2. 초대 링크를 통해 친구들과 비공개로 공유할 수 있다.
3. 친구들이 원하는 금액으로 후원할 수 있다.
4. 회원가입 또는 로그인을 통해 서비스를 시작할 수 있다.

#### 1.2 주요 사용자

- 서비스를 처음 방문한 비회원
- 회원가입을 진행하려는 사용자
- 기존 계정으로 로그인하려는 사용자

### 4. 사용자 동작 및 화면 이동

#### 4.1 회원가입 버튼 클릭

1. 사용자가 랜딩 페이지에 접속한다.
2. 서비스 소개를 확인한다.
3. "회원가입" 버튼을 클릭한다.
4. UI-02 회원가입 화면으로 이동한다.

**이동 화면**
- UI-02 회원가입

#### 4.2 로그인 버튼 클릭

1. 사용자가 랜딩 페이지에 접속한다.
2. "로그인" 버튼을 클릭한다.
3. UI-03 로그인 화면으로 이동한다.

**이동 화면**
- UI-03 로그인

#### 4.3 이미 로그인한 사용자의 접근

1. 로그인된 사용자가 서비스 기본 URL에 접속한다.
2. 시스템이 인증 상태를 확인한다.
3. 인증된 사용자라면 UI-04 홈 화면으로 이동한다.
4. 인증되지 않은 사용자라면 랜딩 페이지를 표시한다.

### UI-02 회원가입 페이지 화면명세서

### 1. 화면 개요

- **화면 ID:** UI-02
- **화면 이름:** 회원가입 페이지
- **화면 목적:** 신규 사용자가 이름, 이메일, 비밀번호, 생년월일을 입력하여 계정을 생성하고 서비스를 이용할 수 있도록 한다.
- **접근 권한:** 비로그인 사용자
- **관련 기능 ID:** F-01 회원가입 및 로그인, F-13 개인정보 보호 및 접근 권한
- **파일명:** `02_signup.md`
- **화면 경로:** `/signup`

#### 1.1 기본 정책

- 모든 사용자는 동일한 회원가입 절차를 이용한다.
- 회원가입 시 생일자와 후원자 역할을 선택하지 않는다.
- 하나의 계정으로 자신의 펀딩을 생성하고 다른 사람의 펀딩에 후원할 수 있다.
- 회원가입 시 생년월일 입력은 필수이다.
- 관심사 및 선물 취향은 회원가입 이후 마이페이지에서 설정할 수 있다.

### 2. 화면 구성 및 배치

#### 2.1 상단 영역

**표시 요소**
- 레트로 창 스타일의 상단 헤더
- 뒤로 가기 아이콘
- 화면 제목: `회원가입`
- 안내 문구: `생일선물을 함께 준비할 계정을 만들어보세요! 🎂`

**버튼 이름**
- `뒤로 가기`

**배치 위치**
- 화면 최상단에 헤더를 배치한다.
- 뒤로 가기 버튼은 왼쪽에 배치한다.
- 화면 제목은 헤더 중앙에 배치한다.
- 안내 문구는 헤더 아래에 배치한다.

**버튼 동작**
- 뒤로 가기를 클릭하면 랜딩 페이지(UI-01)로 이동한다.
- 입력 중인 정보가 있다면 이동 전 확인 안내를 표시한다.

#### 2.2 중앙 영역

**표시 요소**
1. 이름 입력창
2. 이메일 입력창
3. 비밀번호 입력창
4. 비밀번호 확인 입력창
5. 생년월일 선택창

**컴포넌트 배치**
- 모든 입력 요소를 세로 방향으로 배치한다.
- 각 입력창 위에는 항목 이름을 표시한다.
- 필수 입력 항목에는 `*` 표시를 추가한다.
- 입력창 사이 간격은 16px로 설정한다.
- 입력창은 화면 너비에 맞춰 100%로 표시한다.

**데이터 표시 내용**

| 항목 | 입력 방식 | 필수 여부 | 안내 문구 |
|---|---|---|---|
| 이름 | 텍스트 입력 | 필수 | 이름을 입력해 주세요 |
| 이메일 | 이메일 입력 | 필수 | example@email.com |
| 비밀번호 | 비밀번호 입력 | 필수 | 비밀번호를 입력해 주세요 |
| 비밀번호 확인 | 비밀번호 입력 | 필수 | 비밀번호를 다시 입력해 주세요 |
| 생년월일 | 날짜 선택 | 필수 | 생년월일을 선택해 주세요 |

#### 2.3 하단 영역

**표시 요소**

**배치 위치**
- 모든 입력창 아래에 회원가입 버튼을 배치한다.
- 회원가입 버튼 아래에 로그인 안내 문구를 표시한다.

**안내 문구**
`이미 계정이 있으신가요? 로그인`

**고정 여부**
- 회원가입 버튼은 화면 하단에 고정하지 않는다.
- 입력창 아래에 자연스럽게 배치한다.
- 작은 모바일 화면에서는 스크롤하여 접근한다.
- 회원가입 페이지에는 하단 5개 탭 메뉴를 표시하지 않는다.

### 3. UI 컴포넌트 상세

#### 3.1 이름 입력창 (`name-input`)

- **UI 형태:** 일반 텍스트 입력창
- **표시 문구:** `이름 *`
- **Placeholder:** `이름을 입력해 주세요`
- **기본값:** 빈 문자열
- **필수 여부:** 필수
- **클릭 또는 입력 시 동작:** 사용자가 이름을 입력한다.
- **비활성화 조건:** 회원가입 요청 처리 중

**추가 규칙**
- 입력값 앞뒤 공백을 제거한다.
- 공백만 입력한 경우 유효하지 않은 값으로 처리한다.
- 입력한 이름은 사용자 프로필에 저장한다.
- 이후 축하 메시지의 작성자 이름으로 사용한다.

#### 3.2 이메일 입력창 (`email-input`)

- **UI 형태:** 이메일 입력창
- **표시 문구:** `이메일 *`
- **Placeholder:** `example@email.com`
- **기본값:** 빈 문자열
- **필수 여부:** 필수
- **클릭 또는 입력 시 동작:** 이메일 주소를 입력한다.
- **비활성화 조건:** 회원가입 요청 처리 중

**추가 규칙**
- 이메일 형식을 검증한다.
- 이미 가입된 이메일인지 서버에서 확인한다.
- 중복된 이메일로 회원가입할 수 없다.
- 이메일 중복은 데이터베이스에서도 방지한다.

#### 3.3 비밀번호 입력창 (`password-input`)

- **UI 형태:** 비밀번호 입력창
- **표시 문구:** `비밀번호 *`
- **Placeholder:** `비밀번호를 입력해 주세요`
- **기본값:** 빈 문자열
- **필수 여부:** 필수
- **클릭 또는 입력 시 동작:** 비밀번호를 입력한다.
- **비활성화 조건:** 회원가입 요청 처리 중

**추가 규칙**
- 입력 문자는 기본적으로 가려서 표시한다.
- 눈 아이콘을 클릭하면 비밀번호 표시 여부를 변경한다.
- 비밀번호는 최소 8자 이상으로 설정한다.
- 비밀번호는 서버에서 안전하게 해시 처리하여 저장한다.
- 비밀번호 원문을 데이터베이스에 저장하지 않는다.

#### 3.4 비밀번호 확인 입력창 (`password-confirm-input`)

- **UI 형태:** 비밀번호 입력창
- **표시 문구:** `비밀번호 확인 *`
- **Placeholder:** `비밀번호를 다시 입력해 주세요`
- **기본값:** 빈 문자열
- **필수 여부:** 필수
- **클릭 또는 입력 시 동작:** 앞서 입력한 비밀번호와 일치하는지 확인한다.
- **비활성화 조건:** 회원가입 요청 처리 중

**추가 규칙**
- 비밀번호와 비밀번호 확인값이 일치해야 한다.
- 일치하지 않으면 오류 메시지를 표시한다.
- 비밀번호 확인값은 데이터베이스에 저장하지 않는다.

#### 3.5 생년월일 선택창 (`birthday-date-picker`)

- **UI 형태:** 날짜 선택 컴포넌트
- **표시 문구:** `생년월일 *`
- **Placeholder:** `생년월일을 선택해 주세요`
- **기본값:** 선택되지 않은 상태
- **필수 여부:** 필수
- **클릭 또는 입력 시 동작:** 날짜 선택창을 열어 생년월일을 선택한다.
- **비활성화 조건:** 회원가입 요청 처리 중

**추가 규칙**
- 연도, 월, 일을 선택할 수 있다.
- 미래 날짜는 선택할 수 없다.
- 존재하지 않는 날짜는 선택할 수 없다.
- 선택한 날짜는 `YYYY-MM-DD` 형식으로 처리한다.
- 생년월일은 이후 생일 D-day 계산에 사용한다.
- 마이페이지에서 수정할 수 있다.

#### 3.6 회원가입 버튼 (`signup-button`)

- **UI 형태:** Primary 버튼
- **표시 문구:** `회원가입`
- **기본값:** 활성 상태
- **필수 여부:** 해당 없음
- **클릭 시 동작:** 입력값을 검증하고 회원가입 요청을 서버에 전송한다.
- **비활성화 조건:** 회원가입 요청 처리 중

**처리 규칙**
1. 필수 입력값을 확인한다.
2. 이메일 형식을 검증한다.
3. 비밀번호 조건을 확인한다.
4. 비밀번호 확인값의 일치 여부를 검증한다.
5. 생년월일의 유효성을 확인한다.
6. 서버에서 이메일 중복 여부를 확인한다.
7. 검증 성공 시 계정을 생성한다.

**로딩 상태**
- 버튼 문구: `가입 처리 중...`
- 중복 클릭 방지
- 처리 완료 전 추가 요청 방지

#### 3.7 로그인 이동 버튼 (`login-link`)

- **UI 형태:** 텍스트 링크
- **표시 문구:** `로그인`
- **기본값:** 활성 상태
- **필수 여부:** 해당 없음
- **클릭 시 동작:** UI-03 로그인 페이지로 이동한다.
- **비활성화 조건:** 회원가입 요청 처리 중

### 4. 사용자 동작 및 화면 이동

#### 4.1 진입 경로

- 랜딩 페이지(UI-01)에서 `회원가입` 버튼 클릭
- 로그인 페이지(UI-03)에서 회원가입 선택
- 초대 링크를 통해 접속한 비회원이 회원가입 선택

#### 4.2 주요 사용자 행동

1. 사용자가 회원가입 페이지에 접속한다.
2. 이름을 입력한다.
3. 이메일 주소를 입력한다.
4. 비밀번호를 입력한다.
5. 비밀번호 확인을 입력한다.
6. 생년월일을 선택한다.
7. `회원가입` 버튼을 클릭한다.
8. 시스템이 입력값을 검증한다.
9. 서버에서 이메일 중복 여부를 확인한다.
10. 검증에 성공하면 사용자 계정을 생성한다.
11. 회원가입 완료 안내를 표시한다.
12. 로그인 페이지로 이동한다.

#### 4.3 버튼 클릭 시 이동 화면

| 버튼 | 이동 화면 |
|---|---|
| 뒤로 가기 | UI-01 랜딩 |
| 회원가입 성공 | UI-03 로그인 |
| 로그인 | UI-03 로그인 |

#### 4.4 이전 화면 이동

- 기본 진입 시 랜딩 페이지로 이동한다.
- 초대 링크를 통해 진입한 경우 회원가입과 로그인 완료 후 원래 참여 과정을 이어갈 수 있도록 한다.
- 인증되지 않은 사용자는 비공개 펀딩에 접근할 수 없다.

#### 5.3 검증 시점

**입력 중**
- 이메일 형식 안내
- 비밀번호 조건 안내
- 비밀번호 확인값 일치 여부 확인

**입력창 포커스 해제 시**
- 필수 입력 여부 확인
- 입력 형식 검증
- 오류 메시지 표시

**회원가입 버튼 클릭 시**
- 전체 입력값 검증
- 이메일 중복 확인
- 검증 성공 시 계정 생성

**서버 검증**
- 클라이언트 검증과 별개로 모든 필수값을 다시 검증한다.
- 이메일 중복을 데이터베이스 고유 제약조건으로 방지한다.

### 6. 데이터 표시 및 권한

#### 6.1 표시 데이터

- 이름
- 이메일
- 비밀번호 입력 상태
- 비밀번호 확인 입력 상태
- 생년월일
- 입력 오류 메시지
- 회원가입 처리 상태

#### 6.2 생일자 권한

- 회원가입 시 별도의 생일자 권한을 선택하지 않는다.
- 가입 후 자신의 펀딩을 생성하면 해당 펀딩의 생일자 권한을 가진다.

#### 6.3 후원자 권한

- 회원가입 시 별도의 후원자 권한을 선택하지 않는다.
- 가입 후 친구 펀딩에 참여하면 해당 펀딩의 후원자 권한을 가진다.

#### 6.4 비공개 데이터

- 비밀번호는 평문으로 저장하지 않는다.
- 비밀번호는 서버에서 Argon2 등의 안전한 해시 알고리즘으로 처리한다.
- 비밀번호 확인값은 저장하지 않는다.
- 다른 사용자의 계정 정보는 표시하지 않는다.
- 비공개 펀딩 정보는 권한 확인 후에만 제공한다.

### 7. 화면 상태 및 예외 처리

#### 7.1 초기 상태

- 모든 입력창은 비어 있다.
- 생년월일은 선택되지 않은 상태이다.
- 회원가입 버튼이 표시된다.
- 로그인 링크가 표시된다.
- 오류 메시지는 표시하지 않는다.

#### 7.2 로딩 상태

- 회원가입 요청 중 버튼 비활성화
- `가입 처리 중...` 문구 표시
- 동일 요청 중복 전송 방지

#### 7.3 데이터 없음

- 신규 사용자 입력 화면이므로 별도의 빈 데이터 상태는 제공하지 않는다.
- 필수 입력값이 없으면 해당 입력창에 오류 메시지를 표시한다.

#### 7.4 성공 상태

**회원가입 성공**
- 사용자 계정 생성 완료
- 성공 메시지 표시

`회원가입이 완료되었습니다! 로그인해 주세요.`

- UI-03 로그인 페이지로 이동한다.
- 초대 링크에서 진입한 경우 로그인 후 원래 초대 참여 과정을 이어간다.

#### 7.5 실패 상태

**이메일 중복**

`이미 사용 중인 이메일입니다.`

**비밀번호 불일치**

`비밀번호가 일치하지 않습니다.`

**서버 오류**

`회원가입 처리 중 문제가 발생했습니다. 잠시 후 다시 시도해 주세요.`

**네트워크 오류**

`네트워크 연결을 확인한 후 다시 시도해 주세요.`

**처리 원칙**
- 오류 발생 시 이름, 이메일, 생년월일 입력값을 유지한다.
- 필요한 경우 비밀번호를 다시 입력하도록 안내한다.
- 가입 처리 결과가 불명확할 때 중복 계정이 생성되지 않도록 한다.

#### 7.6 권한 없음

- 회원가입 페이지는 비로그인 사용자에게 제공한다.
- 이미 로그인한 사용자가 접근하면 UI-04 홈 화면으로 이동한다.
- 인증 상태 확인 후 적절한 화면을 표시한다.

### 4. 사용자 동작 및 처리 흐름

#### 4.1 일반 로그인

1. 사용자가 랜딩 페이지(UI-01)에서 `로그인`을 클릭한다.
2. 로그인 페이지(UI-03)가 표시된다.
3. 이메일과 비밀번호를 입력한다.
4. 필요한 경우 `로그인 상태 유지`를 선택한다.
5. `로그인` 버튼을 클릭한다.
6. 클라이언트가 필수값과 이메일 형식을 검사한다.
7. 서버가 이메일 및 비밀번호를 검증한다.
8. 인증에 성공하면 로그인 상태를 설정한다.
9. 홈 페이지(UI-04)로 이동한다.

#### 4.2 초대 링크를 통한 로그인

1. 비로그인 사용자가 그룹 또는 펀딩 초대 링크에 접속한다.
2. 인증이 필요하므로 로그인 페이지(UI-03)로 이동한다.
3. 초대 링크의 참여 대상 정보 또는 복귀 경로를 유지한다.
4. 사용자가 로그인에 성공한다.
5. 초대 링크의 유효성과 참여 권한을 확인한다.
6. 초대 확인 및 참여 화면(UI-17)으로 이동하여 참여 과정을 이어서 진행한다.
7. 초대 링크가 만료되었거나 유효하지 않으면 오류를 안내한다.

#### 4.3 회원가입으로 이동

1. 사용자가 `회원가입` 링크를 클릭한다.
2. 회원가입 페이지(UI-02)로 이동한다.
3. 초대 링크를 통해 진입한 경우 초대 참여 정보를 유지한다.

| 이메일 또는 비밀번호 불일치 | 로그인 실패, 화면 유지 | 이메일 또는 비밀번호를 확인해 주세요. |

**보안 및 권한 규칙**
- 로그인 실패 메시지로 특정 이메일의 가입 여부를 노출하지 않는다.
- 비밀번호 원문을 화면 로그나 브라우저 저장 데이터에 기록하지 않는다.
- 보호된 API는 서버에서 인증 및 권한을 확인한다.
- 로그인 이후에도 초대받지 않은 그룹 및 펀딩에는 접근할 수 없다.

### 8. 디자인 적용 기준

- **디자인 기준 문서:** `base.md`
- **디자인 콘셉트:** Y2K 핑크 레트로 + Windows 98 창 스타일
- **화면 구성:** 모바일 우선 반응형 웹, 데스크톱에서 최대 430px 앱 영역 중앙 배치
- **앱 기본 배경:** `#FFFDFD`
- **데스크톱 외부 배경:** `#F8F1FA`
- **기본 강조색:** `#EF78BD`
- **강조 버튼 텍스트:** `#25172A`
- **강조 테두리:** `#30283C`
- **보조 강조색:** 라벤더 `#C8A9EF`, 하늘색 `#B9D7F5`
- **버튼:** 로그인 버튼은 기본 핑크 강조 버튼을 사용한다.
- **입력창:** 공통 입력창 스타일을 사용하고 오류 시 명확한 상태를 표시한다.
- **폰트, 그림자, 테두리, 아이콘:** `base.md`의 공통 토큰과 컴포넌트 규칙을 따른다.
- **하단 탭 메뉴:** 비로그인 화면이므로 표시하지 않는다.

### 9. 구현 시 확인 사항

- 로그인 상태 유지 기능의 구체적인 인증 만료 시간 및 저장 방식은 별도 확정이 필요하다.
- 비밀번호 재설정 기능은 제공된 핵심 로그인 화면 정의에 명시되어 있지 않으므로 이번 화면의 필수 구성에서 제외한다.
- 실제 API 주소와 인증 응답 형식은 백엔드 API 설계 시 확정한다.
- 초대 경유 로그인 후 이동하는 UI-17은 세부 화면 번호 계획에 따라 연결한다.
