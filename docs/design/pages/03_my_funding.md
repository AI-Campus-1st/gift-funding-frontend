### UI-05 내 펀딩 화면명세서

### 1. 화면 개요

- **화면 ID:** UI-05
- **화면 이름:** 내 펀딩
- **화면 목적:** 내가 생성한 펀딩을 진행 중/종료로 나누어 조회하고 관리한다.
- **접근 권한:** 로그인 사용자(조회·관리 권한은 그룹/펀딩별로 구분)
- **관련 기능 ID:** F-07, F-09, F-11, F-12
- **파일명:** `05_my_funding.md`
- **화면 경로:** `/my-funding` (제안 경로, 구현 시 확정)

#### 1.1 기본 정책

- 사용자 및 펀딩별 접근 권한을 서버에서 검증한다.
- 권한이 없는 기능과 정보는 표시하지 않고 API에서도 접근을 차단한다.
- 서비스 공통 디자인은 `base.md`를 따른다.

---

### 2. 화면 구성 및 배치

#### 2.1 상단 영역

**표시 요소**
- 레트로 창 스타일의 상단 헤더
- 화면 제목: `내 펀딩`
- 이전 화면으로 이동하는 뒤로 가기 버튼(주요 탭 화면에서는 생략 가능)

**배치 위치**
- 상단 헤더는 화면 최상단에 배치한다.
- 제목은 헤더 중앙 또는 콘텐츠 시작점에 맞춘다.
- 화면 전환 중에는 중복 요청을 방지한다.

#### 2.2 중앙 영역

**표시 요소**
- 펀딩 이름
- 연결 그룹
- 기간
- 상태
- 선물별 달성률과 생성자에게 허용된 모금액

**컴포넌트 배치**
- 정보와 입력 요소를 세로 방향으로 배치한다.
- 데이터 목록은 카드 또는 항목 단위로 구분한다.
- 접근 권한이 없는 정보는 렌더링하지 않는다.
- 데이터가 없으면 빈 상태 안내와 관련 행동 버튼을 표시한다.

#### 2.3 하단 영역

**표시 요소**
- 주요 행동 버튼 또는 화면 내 이동 링크
- 하단 5개 탭(홈 / 내 펀딩 / 그룹 / 친구 펀딩 / 마이페이지)을 제공한다.

### 4. 사용자 동작 및 처리 흐름

1. 사용자가 `내 펀딩` 화면에 진입한다.
2. 로그인 상태와 접근 권한을 확인한다.
3. 필요한 데이터를 요청하고 로딩 상태를 표시한다.
4. 정상 응답이면 화면의 카드, 입력값, 상태를 표시한다.
5. 사용자가 버튼 또는 항목을 선택하면 유효성 및 권한을 확인한다.
6. 요청 성공 시 갱신된 결과를 보여주거나 관련 화면으로 이동한다.
7. 요청 실패 시 기존 데이터를 임의로 변경하지 않고 오류를 안내한다.

#### 4.1 주요 화면 이동

- `펀딩 만들기` → UI-09
- `펀딩 카드` → UI-12
- `정산 관리` → UI-24
- `축하 편지함` → UI-27

| 네트워크/API 오류 | 오류 메시지와 재시도 동작 제공 |
| 이미 종료/완료된 작업 | 변경 및 후원 불가 상태 표시 |

### 6. 화면 상태 정의

- **초기 상태:** 사용자 및 대상 데이터 확인 전.
- **로딩 상태:** 데이터 조회 또는 요청 처리 중.
- **정상 상태:** 권한이 허용된 데이터를 표시.

- **완료 상태:** 작업이 성공한 경우 결과 반영 또는 다음 화면으로 이동.

#### 3.2 이월 선물 불러오기 (2026-10-16 추가 · F-07, F-11)

- 지난 펀딩에서 이월한 선물이 있으면 선물 목록 영역에 안내 `지난 펀딩에서 이월한 선물이 N개 있어요.`와 `이월 선물 불러오기` 버튼을 표시한다. 없으면 표시하지 않는다.
- 버튼을 누르면 `이월 선물 불러오기` 모달을 연다. 선물마다 체크박스, 이미지, 선물 이름, 지난 펀딩 이름, `이월 {금액} · 목표 {금액}`을 표시한다.
- 모달 버튼: `N개 불러오기`(선택 0개면 `선택 완료`) · `취소`. 취소하면 선택이 바뀌지 않는다.
- 불러온 선물은 선물 목록에 `이월` 배지와 `목표 {금액} · 이월 {금액} 포함`으로 표시한다. 정보는 수정할 수 없고 × 버튼으로 불러오기만 취소한다.
- 불러온 선물도 "선물 최소 1개" 조건에 포함한다. 그룹은 지난 펀딩과 다르게 선택할 수 있다.
- 다른 화면에서 이미 다시 연 이월 선물이면 생성 시 오류를 안내하고 목록을 새로 고친다.

7. 요청 실패 시 기존 데이터를 임의로 변경하지 않고 오류를 안내한다.

#### 4.1 주요 화면 이동

- `뒤로 가기` → UI-12
- `선물 필터` → UI-13

### 5. 입력값 검증 및 예외 처리

| 상황 | 처리 방식 |
|---|---|
| 로그인하지 않음 | 로그인 화면(UI-03)으로 이동, 필요한 경우 복귀 경로 보존 |
| 접근 권한 없음 | 비공개 데이터 숨김, 접근 불가 안내 |
| 데이터 없음 | 빈 상태 문구 및 가능한 다음 행동 표시 |
| 로딩 중 | 로딩 표시 및 중복 제출 방지 |
| 네트워크/API 오류 | 오류 메시지와 재시도 동작 제공 |
| 이미 종료/완료된 작업 | 변경 및 후원 불가 상태 표시 |

### 6. 화면 상태 정의

- **초기 상태:** 사용자 및 대상 데이터 확인 전.
- **로딩 상태:** 데이터 조회 또는 요청 처리 중.
- **정상 상태:** 권한이 허용된 데이터를 표시.
- **빈 상태:** 표시할 항목이 없는 경우.
- **오류 상태:** 입력 검증 실패, 네트워크 오류, 접근 제한.
- **완료 상태:** 작업이 성공한 경우 결과 반영 또는 다음 화면으로 이동.
