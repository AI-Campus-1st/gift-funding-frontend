## 4. 선물 (F-04) · AI 추천 (F-03)

### 4.1 선물 등록 · 수정 · 삭제 (UI-10, API F5~F8)

**1) 규칙 · 흐름**
- 등록 경로 두 가지: 펀딩 생성 중(임시 목록에 담았다가 펀딩과 함께 저장) / 이미 만든 펀딩에 추가.
- 필수 4항목: 선물 이름 · 실제 가격 · 이미지 · 상품 구매 URL. 설명은 선택.
- **선물 가격 = 그 선물의 목표 금액.**
- 등록 · 수정 · 삭제는 그 펀딩의 생일자만.
- 후원(또는 📌 이월 금액)이 있는 선물은 **가격 변경과 삭제를 제한**한다. 이름 · 이미지 · URL · 설명은 수정할 수 있다. (F-04)
- 📌 펀딩에는 선물이 최소 1개 있어야 하므로 마지막 선물은 삭제할 수 없다. (F-07 "최소 한 개 이상의 선물")
- 📌 삭제는 공통 삭제 확인 모달을 거친다. (rules.md 10.3)

**2) 입력 · 결과**: `GiftInput { name, price, image_url, product_url, description }` → 생성 `201 { id }` · 수정/삭제 `204` · 수정 화면 조회 `GiftEditDto { ..., has_donations }`

**3) 검증**

| 항목 | 조건 | 문구 | 위치 |
|---|---|---|---|
| 이름 | 비어 있음 | 선물 이름을 입력해 주세요. | ✅ 프론트 ✅ Mock |
| 가격 | 비어 있음 / 0원 이하 | 선물 가격을 입력해 주세요. / (0원보다 큰 금액) | ✅ 프론트 ✅ Mock |
| 가격 최대 📌 | 50,000,000원 초과 (2026-10-19 확정) | 선물 가격은 50,000,000원 이하로 입력해 주세요. | ✅ 프론트 ✅ Mock 🔧 백엔드 |
| 이미지 | 없음 / 허용되지 않은 형식 | 선물 이미지를 등록해 주세요. / 형식 안내 | ✅ 프론트 · 📌 JPG · PNG · WEBP · GIF, 5MB (Q2) |
| URL | 형식 오류 | (올바른 URL 형식) | ✅ 프론트 ✅ Mock |
| 가격 변경 | 후원 · 이월 금액 있음 | 후원 또는 이월 금액이 있는 선물은 가격(목표 금액)을 변경할 수 없어요. | ✅ 프론트(입력 잠금) ✅ Mock |
| 삭제 | 후원 · 이월 금액 있음 / 마지막 선물 | 후원이 발생한 선물은 삭제할 수 없어요. / 펀딩에는 선물이 최소 1개 있어야 해요. | ✅ 프론트(버튼 잠금) ✅ Mock |

**4) 예외**: 권한 없음 `403` · 잠긴 선물 `409 GIFT_LOCKED` · 삭제 실패 시 모달 안에 오류, 데이터 유지 ✅ 프론트

**5) 데이터 · API**: `gifts` · `POST /fundings/{id}/gifts`, `GET /me/gifts/{id}`, `PUT/DELETE /gifts/{id}`

**6) FastAPI 구현 항목** 🔧
- 가격 변경 · 삭제 전에 선물 행을 잠그고 후원 존재 여부 확인 (확인 직후 후원이 들어오는 경쟁 상황 방지)
- `donations.gift_id` `ON DELETE RESTRICT` 안전장치
- 이미지 파일 업로드 · 형식 검증

📌 **확정 (Q8 · Q8-1)**: 선물 **추가**는 펀딩이 끝나기 전(시작일 전 "예정" 기간 포함, 진행 중)에는 언제든 가능하고, **종료된 펀딩에는 불가**하다. 종료된 펀딩에 추가 요청 → `409 FUNDING_NOT_ACTIVE` "종료된 펀딩에는 선물을 추가할 수 없어요." (현재: ✅ 프론트는 종료 후 버튼 숨김 · ✅ Mock 서버 차단 · 🔧 백엔드)

### 4.2 AI 선물 추천 (UI-11, API R1)

**1) 규칙 · 흐름**
- 저장된 취향을 기본 조건으로 불러온다. 관심사 · 카테고리 · 예산을 바꿔 요청할 수 있다.
- 결과: 추천 이름 · 추천 이유 · 예상 가격대 · 카테고리. **참고용**이며 자동 등록되지 않는다.
- "선물로 등록" → 선물 등록 화면에 이름만 채워서 이동. 실제 가격 · 이미지 · URL은 생일자가 확인해 입력한다.
- "다시 추천받기"는 이전 결과를 제외(`exclude_ids`)하고 다른 후보를 우선한다.

**2) 입력 · 결과**: `{ keywords, categories, budget_min, budget_max, exclude_ids }` → `{ items: [{ id, name, reason, category, price_min, price_max }] }`

**3) 검증**: 조건이 하나도 없으면 `VALIDATION` "관심사, 카테고리, 예산 중 하나 이상 입력해 주세요." ✅ Mock

**4) 예외**: 결과 없음 → "조건에 맞는 추천 결과가 없어요." ✅ 프론트 · 실패 → 재시도 안내 · AI 응답 형식 오류 → `502 AI_UNAVAILABLE` 🔧

**5) 데이터 · API**: 저장 데이터 없음 · `POST /ai/recommendations`

**6) FastAPI 구현 항목** 🔧: OpenAI API 호출(httpx, 키는 서버 환경 변수), 응답 JSON 형식 검증 · 가격 숫자 검증, 시간 초과 처리
