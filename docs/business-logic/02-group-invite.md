## 3. 그룹 · 초대 (F-05, F-06)

### 3.1 그룹 생성 · 조회 (UI-06, UI-14, UI-15, API G1~G3)

**1) 규칙 · 흐름**
- 그룹 이름(필수) · 설명(선택)으로 만든다. 만든 사람이 **관리자**가 되고 참여자 목록에도 들어간다.
- 그룹은 비공개다. 참여자만 상세(이름 · 설명 · 참여자 · 연결 펀딩)를 볼 수 있다.
- 그룹 목록은 "내가 만든 그룹 / 참여 중인 그룹"으로 나눈다.
- 그룹 이름과 펀딩 이름은 별개다.
- 📌 **그룹 삭제 · 참여자 제외 · 그룹 나가기는 제공하지 않는다.** (plan.md 7.1 D8)

**2) 입력 · 결과**: `{ name, description }` → `201 { id }` · 상세: `GroupDetailDto`(참여자 이름 · 관리자 여부만, 이메일 비공개)

**3) 검증**: 이름 필수 "그룹 이름을 입력해 주세요." ✅ 프론트 ✅ Mock · 📌 이름 30자 · 설명 100자 (Q1 확정) "그룹 이름은 30자 이내로 입력해 주세요." ✅ 프론트 ✅ Mock

**4) 예외**: 없는 그룹 `404` · 참여자가 아님 `403`

**5) 데이터 · API**: `groups`, `group_members` · `GET /groups`, `POST /groups`, `GET /groups/{id}`, `PATCH /groups/{id}`

**6) FastAPI 구현 항목** 🔧: 그룹 + 관리자 참여 행을 한 트랜잭션으로 생성, `(group_id, user_id)` 복합 PK

**📌 그룹 정보 수정 (Q9, 2026-10-19 확정)**: 그룹 이름 · 설명은 **그룹을 만든 사람(관리자)만** 수정한다. 검증은 생성과 같다. 아니면 `403` "그룹 관리자만 수정할 수 있어요." · `PATCH /groups/{id}` (G9) ✅ 프론트(UI-15 "그룹 정보 수정" 모달) ✅ Mock 🔧 백엔드

**📌 펀딩 여는 그룹 (2026-10-19 확정)**: 펀딩은 **그 그룹을 만든 사람만** 열 수 있다. 예) 서연이 생일 → 서연이 만든 "대학 친구들"에 펀딩을 연다. 지훈이 생일 → 지훈이 자기 그룹을 따로 만들어 연다. 한 사람이 그룹을 여러 개 만들 수 있고 그룹마다 펀딩을 열 수 있다. 그룹 상세의 "펀딩 만들기" 버튼도 만든 사람에게만 보인다.

### 3.2 초대 링크 관리 (UI-16, API G4~G6)

**1) 규칙 · 흐름**
- 링크 관리 권한: **그룹 관리자(그룹의 모든 링크)** 또는 **펀딩 생일자(본인 펀딩에 지정한 링크)**. (F-06 "그룹 또는 펀딩 관리 권한")
- 링크 종류: 그룹 링크(펀딩 지정 없음) · 펀딩 지정 링크(참여 후 그 펀딩으로 바로 이동).
- 생성 · 복사 · 비활성화를 할 수 있다. 비활성화는 확인 모달을 거친다. 이미 참여한 사람은 그대로 유지된다.
- 📌 펀딩 지정 링크는 **그 펀딩이 끝나면 만료**된다. 그룹 링크는 비활성화 전까지 유효하다. (D-S1-4) → 목록에 "만료됨" 표시, 복사 · 비활성화 버튼 숨김.

**2) 입력 · 결과**: 생성 `{ funding_id | null }` → `InviteDto { token, is_active, is_expired, ... }` · 비활성화 `{ is_active: false }` → `204`

**3) 검증**: 펀딩 지정 시 그 그룹에 연결된 펀딩만 ✅ Mock · 생일자는 본인 펀딩 링크만 ✅ Mock

**4) 예외**: 권한 없음 `403` · 다른 그룹 펀딩 지정 `400` · 없는 링크 `404`

**5) 데이터 · API**: `invites` · `GET/POST /groups/{id}/invites`, `PATCH /invites/{token}`

**6) FastAPI 구현 항목** 🔧: `secrets.token_urlsafe`로 예측 불가 토큰, `token` UNIQUE, `created_by` 기록, 만료는 저장하지 않고 펀딩 종료일로 계산

### 3.3 초대 확인 · 참여 (UI-17, API G7 · G8)

**1) 규칙 · 흐름** (F-06 참여 흐름 1~8)
1. 친구 펀딩 화면에서 링크 · 토큰을 직접 입력하거나, 공유 링크(`/join-invite?token=`)로 들어온다.
2. 로그인하지 않았으면 로그인 후 같은 화면으로 돌아온다. ✅ 프론트
3. 링크를 확인하고 참여 대상(그룹 이름 · 펀딩 이름 · 생일자 이름)을 보여준다.
4. "참여하기" → 그룹 참여자로 등록 → 펀딩 상세로 이동(내 펀딩이면 관리 화면, 아니면 친구 펀딩 상세).
5. 이미 참여했으면 중복 등록하지 않고 같은 결과로 이동한다.
6. 📌 이동할 펀딩 (2026-10-19 확정): 링크에 지정된 펀딩 → 없으면 그 그룹의 진행 중인 다른 사람 펀딩 중 시작일이 가장 최근인 것 → 없으면 그룹 상세 (예정 · 종료 펀딩으로는 자동 이동하지 않음, 그룹 상세 목록에서 고름). 서버는 참여 저장을 마친 뒤 응답한다 → 바로 펀딩 상세로 가도 권한이 있다.

**2) 입력 · 결과**: `token` → 미리보기 `InvitePreviewDto` · 참여 `JoinResultDto { group_id, target_funding_id, target_is_mine, already_joined }` (화면 경로는 프론트가 만든다 ✅ 프론트 `mappers.ts`)

**3) 검증 · 예외**

| 상황 | 코드 | 문구 |
|---|---|---|
| 없는 링크 | `404 INVITE_INVALID` | 유효하지 않거나 만료된 초대 링크입니다. |
| 비활성화된 링크 | `410 INVITE_INACTIVE` | 비활성화된 초대 링크라 참여할 수 없어요. 친구에게 새 링크를 요청해 주세요. |
| 펀딩이 끝난 링크 | `410 INVITE_EXPIRED` | 펀딩이 종료되어 만료된 초대 링크입니다. |
| 참여 처리 실패 | `500` | 참여 처리 중 문제가 발생했어요. 잠시 후 다시 시도해 주세요. |

**5) 데이터 · API**: `invites`, `group_members` · `GET /invites/{token}`, `POST /invites/{token}/join`

**6) FastAPI 구현 항목** 🔧: 참여 등록 시 `(group_id, user_id)` 충돌은 "이미 참여"로 처리(INSERT … ON CONFLICT DO NOTHING), 링크 검증 → 참여 → 이동 대상 계산을 한 트랜잭션
