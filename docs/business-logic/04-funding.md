## 5. 펀딩 (F-07, F-09, F-13)

### 5.1 펀딩 생성 (UI-09, API F3)

**1) 규칙 · 흐름**
1. 펀딩 이름(그룹 이름과 별개) · 그룹 · 시작일 · 종료일을 입력하고 선물을 1개 이상 담는다.
2. 선물 등록 · AI 추천 화면을 오가도 입력이 유지된다. ✅ 프론트(`fundingDraft`, 탭 단위 임시 저장)
3. 펀딩을 만든 사람이 생일자가 된다. 📌 **본인이 만든 그룹에만** 열 수 있다 (참여만 한 그룹은 불가, 2026-10-19 확정).
4. 📌 지난 펀딩에서 이월한 선물을 **불러와 다시 열 수 있다**(5.5).
5. 성공하면 내 펀딩 상세(UI-12)로 이동한다.

**2) 입력 · 결과**: `{ name, group_id, start_date, end_date, gifts[], carryover_ids[] }` → `201 { id }`

**3) 검증**

| 항목 | 조건 | 문구 | 위치 |
|---|---|---|---|
| 이름 | 비어 있음 | 펀딩 이름을 입력해 주세요. | ✅ 프론트 ✅ Mock |
| 그룹 📌 | 미선택 / 내가 만든 그룹이 아님 | 그룹을 선택해 주세요. / 내가 만든 그룹에만 펀딩을 열 수 있어요. | ✅ 프론트(내가 만든 그룹만 목록에 표시) ✅ Mock 🔧 백엔드 |
| 시작일 · 종료일 | 미선택 / 종료일 < 시작일 | 시작일을 선택해 주세요. / 종료일은 시작일보다 빠를 수 없어요. | ✅ 프론트 ✅ Mock |
| 선물 | 0개 (직접 등록 + 불러온 이월 선물) | 선물을 최소 1개 이상 등록해 주세요. | ✅ 프론트 ✅ Mock |
| 각 선물 | 4.1과 같음 | — | ✅ Mock |
| 시작일 📌 Q6 | 오늘보다 이전 (오늘은 가능 → 바로 진행 중) | 시작일은 오늘 이전으로 선택할 수 없어요. | ✅ 프론트(날짜 선택 제한) ✅ Mock · 🔧 백엔드 |
| 기간 📌 Q6 | 시작일부터 종료일까지 3주(시작일 포함 21일) 초과 | 펀딩 기간은 최대 3주(21일)까지 설정할 수 있어요. | ✅ 프론트(날짜 선택 제한) ✅ Mock · 🔧 백엔드 |
| 동시 진행 개수 📌 Q18 | 제한 없음 (진행 중 · 예정 펀딩이 있어도 새로 만들 수 있음) | — | ✅ Mock |

**4) 예외**: `400 VALIDATION`(필드별) · `403` · 이월 기록 없음 `404` · 이미 다시 연 이월 `409 CONFLICT` → 이월 목록 새로 고침 ✅ 프론트

**5) 데이터 · API**: `fundings`, `gifts`, `carryovers` · `POST /fundings`

**6) FastAPI 구현 항목** 🔧: 펀딩 + 선물 + 이월 반영을 한 트랜잭션, 이월 기록은 `SELECT … FOR UPDATE`로 잠근 뒤 `pending` 확인

### 5.2 펀딩 조회 · 모금 현황 (UI-04, 05, 07, 12, 18, API F1 · F2 · F10 · F11)

**1) 규칙 · 계산** (F-09, FEATURE_SPEC 4.3)

| 값 | 계산 | 공개 |
|---|---|---|
| 목표 금액 | 선물 가격 | 생일자 · 후원자 |
| 현재 모금액 | 정상 처리된 후원 합계 **+ 📌 다시 연 이월 금액** | 생일자만 |
| 남은 금액 | 목표 − 현재 모금액 (0 미만 없음) | 생일자만 (초과 후원 오류 때만 예외적으로 `max_available`) |
| 달성률 | ⌊현재 모금액 ÷ 목표 × 100⌋, 최대 100 | 생일자 · 후원자 |
| 후원 마감 | 달성률 100% | 생일자 · 후원자 |
| 펀딩 상태 | 1.4 날짜 규칙 | 생일자 · 후원자 |
| 펀딩 총 모금액 | 선물 모금액 합 | 생일자만 |

- 📌 달성률은 **선물별**로 보여준다. 펀딩 전체 목표를 합산하지 않는다. (DEFINITION, plan.md D5 — 홈 친구 펀딩 카드 포함)
- 내 펀딩 = 내가 만든 펀딩, 친구 펀딩 = 내가 참여한 그룹의 다른 사람 펀딩. 시작일 최신순.

**2) 결과**: 생일자 `OwnerFundingDto` · 후원자 `FriendFundingDto`(모금액 필드 없음)

**4) 예외**: 다른 사람 펀딩을 생일자 화면으로 조회 `403` · 본인 펀딩을 친구 화면으로 조회 `403` "본인 펀딩은 내 펀딩 메뉴에서 관리해 주세요."

**5) 데이터 · API**: `fundings`, `gifts`, `donations`, `carryovers` · `GET /me/fundings(/{id})`, `GET /fundings/friends`, `GET /fundings/{id}`

**6) FastAPI 구현 항목** 🔧: 집계 쿼리(선물별 SUM), 권한별 Pydantic 응답 모델 분리(후원자 모델에는 금액 필드 자체가 없게), 목록 N+1 방지

**현재 구현**: ✅ Mock(`access.ts`의 계산 · 권한별 뷰) · ✅ 프론트(타입 분리: 후원자 타입에 모금액 필드 없음)

### 5.4 펀딩 삭제 (UI-12, API F4)

**1) 규칙 · 흐름** 📌 (plan.md D6 · D7, FEATURE_SPEC F-07 추가 규칙)
- 생일자만 삭제할 수 있다. **후원이 한 건이라도 있거나 이월 금액이 들어간 펀딩은 삭제할 수 없다.** 진행 상태(예정 · 진행 · 종료)와는 관계없다.
- 삭제 버튼 → 공통 삭제 확인 모달 → "삭제" → Hard Delete → "삭제되었습니다." → 내 펀딩 목록.
- 함께 삭제: 선물, 이 펀딩 지정 초대 링크, **이 펀딩과 연결된 알림**. 연결 해제: 생일 일정의 펀딩 연결(null).

**3) 검증 · 4) 예외**: 후원 있음 `409` "후원이 들어온 펀딩은 삭제할 수 없어요." · 이월 포함 `409` "이월 금액이 포함된 펀딩은 삭제할 수 없어요." · 화면은 미리 버튼을 끄고 이유를 보여준다 ✅ 프론트

**5) 데이터 · API**: DATA_MODEL 6.4 · `DELETE /fundings/{id}`

**6) FastAPI 구현 항목** 🔧: 한 트랜잭션에서 펀딩 행 잠금 → 후원 · 이월 확인 → 연결 데이터 삭제 · 해제. FK `ON DELETE CASCADE / SET NULL / RESTRICT` 설정.

### 5.5 이월 선물 다시 열기 (UI-09 · UI-23 · UI-12, API F13 · F3)

**1) 규칙 · 흐름** 📌 (D-S1-3)
1. 목표 미달 처리에서 "다음 생일로 이월"을 고르면 이월 기록이 `pending`으로 남는다. (7.1)
2. 다음 생일 펀딩을 만들 때 "이월 선물 불러오기"로 고른다. 그룹은 새로 고를 수 있다.
3. 서버가 지난 선물을 같은 이름 · 가격 · 이미지 · URL · 설명으로 복사하고, 이월 금액을 **시작 모금액**으로 넣는다.
4. 이월 기록은 `reopened`가 되고, 같은 기록으로 두 번 열 수 없다.
5. 후원자에게는 이월 금액이 달성률로만 보인다.
6. 다시 연 선물은 가격 변경 · 삭제가 잠기고, 그 펀딩은 삭제할 수 없다.

**2) 입력 · 결과**: 목록 `GET /me/carryovers?status=pending` → `PendingCarryoverDto[]` · 생성 시 `carryover_ids`

**4) 예외**: 다른 사람 기록 `404` · 이미 다시 연 기록 `409`

**6) FastAPI 구현 항목** 🔧: 5.1 트랜잭션 안에서 처리, `carryovers.reopened_gift_id` UNIQUE

📌 **확정 (Q13)**: 다시 연 선물이 또 목표에 못 미치면 **다시 이월할 수 있다.** 목표를 달성(완료)할 때까지 몇 번이든 이월할 수 있고, 이월 금액은 누적된다. (✅ Mock 이미 이렇게 동작)

**현재 구현**: ✅ 프론트(불러오기 모달 · 안내) · ✅ Mock(복사 · 상태 변경 · 모금액 합산)

### 5.6 펀딩 정보 수정 (UI-12, API F14 — 신규 설계, 미구현)

**1) 규칙 · 흐름** 📌 (2026-10-16 확정 Q7)

| 항목 | 시작 전 (`scheduled`) | 진행 중 (`active`) | 종료 (`ended`) |
|---|---|---|---|
| 펀딩 이름 | ✅ 변경 가능 | ✅ 변경 가능 | ❌ 불가 |
| 기간 (시작일 · 종료일) | ❌ 불가 | ❌ 불가 | ❌ 불가 |
| 연결 그룹 | ❌ 불가 | ❌ 불가 | ❌ 불가 |
| 그룹 인원 추가 (초대 링크로 참여) | ✅ 가능 | ✅ 가능 | — (펀딩 지정 링크는 만료, D-S1-4) |

- 생일자만 수정할 수 있다.
- 📌 연결 그룹은 **펀딩을 만든 뒤에는 바꿀 수 없다** (시작 전 포함, 2026-10-16 변경). 그룹은 펀딩을 만들 때 신중히 고른다.
- 진행 중 그룹 인원 추가는 기존 초대 링크 기능(3.2 · 3.3)으로 한다. 새 기능은 필요 없다.

**2) 입력 · 결과**: `{ name }` → `200 OwnerFundingDto` · 기간 · 그룹 필드는 받지 않는다

**3) 검증**

| 조건 | 결과 |
|---|---|
| 생일자 아님 | `403` |
| 이름이 비어 있음 | `400` "펀딩 이름을 입력해 주세요." |
| 종료된 펀딩의 이름 변경 | `409 FUNDING_NOT_ACTIVE` "종료된 펀딩은 수정할 수 없어요." |
| 기간 · 그룹 변경 요청 | `400` "펀딩 기간과 연결 그룹은 수정할 수 없어요." |

**5) 데이터 · API**: `fundings.name`, `fundings.updated_at` · `PATCH /fundings/{funding_id}` (API_SPEC F14)

**6) FastAPI 구현 항목** 🔧: 생일자 확인 → 상태(서버 날짜 기준)가 종료가 아닌지 확인 → 이름 검증 → 저장

**현재 구현**: ✅ 화면(UI-12 펀딩 정보 아래 "펀딩 이름 수정" 버튼 → 모달, 종료된 펀딩에는 버튼 없음) · ✅ Mock(`PATCH /fundings/{id}`) → 🔧 백엔드
