## 8. 생일 캘린더 · 알림 (F-15, F-16)

### 8.1 생일 캘린더 (UI-28, API C1~C5)

**1) 규칙 · 흐름**
- 친구 이름 · 생일을 등록 · 수정 · 삭제한다. 본인 일정만 관리한다. 월별로 보고 매년 반복 표시한다.
- 일정에 **열람 권한이 있는 펀딩**만 연결할 수 있다. 연결 펀딩을 누르면 그 펀딩 상세로 이동한다.
- 권한 없는 펀딩은 연결돼 있어도 이름조차 보여주지 않는다.
- 📌 일정을 삭제하면 **그 일정의 알림도 함께 삭제**한다(D-S1-1). 삭제는 공통 삭제 확인 모달.

**2) 입력 · 결과**: `{ friend_name, birthday, linked_funding_id }` → 생성 `201 { id }` · 목록 `BirthdayEventDto[]`

**3) 검증**: 이름 필수 "친구 이름을 입력해 주세요." · 생일 필수 · 유효 날짜 "올바른 생일을 선택해 주세요." · 연결 펀딩 권한 "접근 가능한 펀딩만 연결할 수 있어요." ✅ 프론트 ✅ Mock

**4) 예외**: 없는 일정 `404` · 다른 사람 일정 `403`

**6) FastAPI 구현 항목** 🔧: 연결 펀딩 권한 검사, 일정 삭제 시 알림 CASCADE

### 8.2 알림 (UI-29 · 홈 빨간 점, API N1~N4)

**1) 규칙 · 흐름**
- 등록된 생일 일정으로 **하루 전 · 당일** 알림을 만든다. 서비스 안에서만 확인한다.
- 📌 미달 선물을 펀딩 종료 후 7일 안에 처리하지 않으면 생일자에게 **미달 처리 알림**(`shortfall-reminder`)을 보낸다. 누르면 목표 미달 처리 화면(UI-23)으로 간다. (Q12)
- 같은 일정 · 같은 날짜 · 같은 유형의 알림은 한 번만 만든다.
- 읽지 않은 알림이 있으면 홈 상단 알림 아이콘에 빨간 점. 열면 읽음 처리, "모두 읽음" 가능.
- 알림을 누르면 열람 가능한 연결 펀딩 상세로, 아니면 생일 캘린더로 이동한다(경로는 프론트가 만든다).
- 📌 생일 알림은 펀딩 ID를 저장하지 않고, 볼 때 일정의 **현재** 연결 펀딩과 권한으로 이동 대상을 정한다. 그래서 연결 펀딩이 삭제돼도 알림은 남고(누르면 캘린더), 목록 조회가 깨지지 않는다. 펀딩을 지우면 그 펀딩의 **미달 처리 알림만** 함께 삭제한다. (2026-10-19 확정)
- 권한 없는 펀딩의 비공개 정보는 알림 내용에 넣지 않는다.

**2) 결과**: `NotificationDto[]`(이동 대상 정보 포함) · 읽지 않은 수 `{ count }`

**4) 예외**: 생성 실패는 서버 로그 기록 · 없는 알림 읽음 처리 `404`

**6) FastAPI 구현 항목** 🔧
- APScheduler 일일 작업: 모든 사용자의 일정 중 "내일 · 오늘" 생일을 찾아 알림 생성
- `(user_id, dedupe_key)` UNIQUE로 중복 방지(작업이 두 번 돌아도 안전)
- 📌 지금은 알림을 볼 때 생성, 나중에 매일 0시 스케줄러. 2월 29일생은 평년에 2월 28일 기준 (Q17)
