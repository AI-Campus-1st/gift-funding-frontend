## 2. 사용자 관리 (F-01, F-02)

### 2.1 회원가입 (UI-02, API A1)

**1) 규칙 · 처리 흐름**
1. 이름 · 이메일 · 비밀번호 · 비밀번호 확인 · 생년월일을 입력한다. 역할(생일자/후원자)은 고르지 않는다.
2. 입력 중 · 포커스 해제 · 제출 시점에 화면이 형식을 검사한다. (01_auth 5.3)
3. 서버가 모든 값을 다시 검증하고 이메일 중복을 확인한다.
4. 비밀번호는 해시로 저장한다. 비밀번호 확인값은 저장하지 않는다.
5. 성공하면 로그인 화면(UI-03)으로 이동한다. 초대 링크로 들어온 경우 복귀 경로를 유지한다.

**2) 입력 · 결과**

| 입력 | 결과 |
|---|---|
| `name`, `email`, `password`, `password_confirm`, `birthday`(YYYY-MM-DD) | `201 { id }` |

**3) 실행 조건 · 검증** (01_auth 5.2 문구 그대로)

| 항목 | 조건 | 오류 문구 | 위치 |
|---|---|---|---|
| 이름 | 비어 있음 / 공백만 | 이름을 입력해 주세요. / 올바른 이름을 입력해 주세요. | ✅ 프론트 ✅ Mock |
| 이메일 | 비어 있음 / 형식 오류 / 중복 | 이메일을 입력해 주세요. / 올바른 이메일 형식으로 입력해 주세요. / 이미 사용 중인 이메일입니다. | ✅ 프론트(형식) ✅ Mock(중복) |
| 비밀번호 | 비어 있음 / 8자 미만 | 비밀번호를 입력해 주세요. / 비밀번호는 8자 이상 입력해 주세요. | ✅ 프론트 ✅ Mock |
| 비밀번호 확인 | 비어 있음 / 불일치 | 비밀번호를 다시 입력해 주세요. / 비밀번호가 일치하지 않습니다. | ✅ 프론트 ✅ Mock |
| 생년월일 | 미선택 / 미래 날짜 / 없는 날짜 | 생년월일을 선택해 주세요. / 오늘 이후 날짜는 선택할 수 없습니다. / 올바른 생년월일을 선택해 주세요. | ✅ 프론트 ✅ Mock |
| 이름 최대 길이 📌 Q1 | 50자 초과 | 이름은 50자 이내로 입력해 주세요. | ✅ 프론트(maxLength) ✅ Mock |

**4) 예외 · 오류**
- 필드 오류 → `400 VALIDATION` + `field_errors`. 이메일 중복 → `409 DUPLICATE_EMAIL` + `field_errors.email`.
- 처리 중 중복 제출 → 버튼 잠금 ✅ 프론트.

**5) 데이터 · API**: `users`(DATA_MODEL 6.2.1) · `POST /auth/signup`

**6) FastAPI 구현 항목** 🔧
- Pydantic 스키마로 형식 검증 + 위 문구로 `field_errors` 구성
- 이메일 소문자 정규화, `users.email` UNIQUE 제약 위반을 `DUPLICATE_EMAIL`로 변환 (동시 가입 대비)
- Argon2 해시 저장, `user_preferences` 빈 행 함께 생성

### 2.2 로그인 · 로그아웃 · 로그인 상태 유지 (UI-03, API A2 · A3 · A4)

**1) 규칙 · 처리 흐름**
1. 이메일 · 비밀번호 입력 → 화면이 필수값 · 이메일 형식 검사 → 서버 인증.
2. 실패 문구는 가입 여부를 드러내지 않도록 하나로 통일한다: "이메일 또는 비밀번호를 확인해 주세요."
3. 성공하면 토큰을 받고, "로그인 상태 유지"를 선택했으면 브라우저를 닫아도 유지(localStorage), 아니면 탭을 닫으면 삭제(sessionStorage).
4. 성공 후 홈(UI-04) 또는 복귀 경로(초대 참여 화면)로 이동한다.
5. 로그아웃하면 토큰과 화면 캐시를 모두 지운다.
6. 토큰이 만료되면 `401` → 로그인 화면으로 이동해 다시 로그인한다.

**2) 입력 · 결과**: `{ email, password, remember_me }` → `{ access_token, token_type, expires_in, user }`

**3) 조건 · 검증**: 비로그인 상태에서만 로그인 화면 사용(로그인 상태면 홈으로) ✅ 프론트(`GuestOnly`)

**4) 예외**: 인증 실패 `401 INVALID_CREDENTIALS` · 만료 `401 UNAUTHORIZED` · 외부 사이트로의 복귀 경로는 무시 ✅ 프론트(`getSafeRedirect`)

**5) 데이터 · API**: `users` · `POST /auth/login`, `POST /auth/logout`, `GET /me`

**6) FastAPI 구현 항목** 🔧
- JWT 발급 · 검증(공통 의존성), Argon2 비밀번호 확인
- 📌 토큰 유효기간 30일 (Q16, 2026-10-19). `remember_me`는 브라우저를 닫아도 유지할지만 정한다
- 📌 로그인 실패 횟수 제한 · 비밀번호 찾기 · 탈퇴는 이번 범위에서 제외 (Q20). 📌 비밀번호 변경은 2026-10-21 추가: 현재 비밀번호 확인 · 현재와 같은 비밀번호 금지 · 8자 이상 · 변경 후 로그인 유지 (Q20-1, `docs/features/password-change.md`) ✅ 프론트 ✅ Mock ✅ 백엔드

**현재 구현**: ✅ 프론트(토큰 보관 · 캐시 비우기 · 복귀 경로) · ✅ Mock(해시 비교 · Mock 토큰)

### 2.3 프로필 조회 · 수정 (UI-08, UI-25, API A4 · A5)

**1) 규칙**: 이름 · 생일 · 프로필 사진을 수정한다. 이메일은 조회만 한다. 본인 정보만 수정할 수 있다.

**2) 입력 · 결과**: `{ name, birthday, profile_image_url }` → 수정된 `UserDto`

**3) 검증**: 이름(2.1과 같음), 생일(유효한 날짜 · 미래 불가), 이미지 형식 · 용량 → 📌 JPG · PNG · WEBP · GIF, 5MB, 업로드 전 축소 (Q2)

**4) 예외**: 잘못된 날짜 · 형식 → `VALIDATION` · 허용되지 않은 이미지 → 화면 오류 안내 ✅ 프론트 · 저장 실패 → 입력값 유지

**5) 데이터 · API**: `users` · `PATCH /me`

**6) FastAPI 구현 항목** 🔧: 이미지 업로드 API(스토리지 저장 후 URL 반환) — 지금은 data URL을 그대로 저장 (DATA_MODEL 6.1)

### 2.4 선물 취향 (UI-26, API A6 · A7)

**1) 규칙 · 흐름** (📌 사용자 요청으로 확정된 화면 동작)
- 입력 폼은 빈 상태로 시작한다. 관심사 키워드를 입력하면 `#키워드` 칩이 생긴다.
- "취향 저장"은 입력 내용을 **기존 취향에 추가**한다(키워드 · 카테고리는 합치고 중복 제외, 가격대는 선택했을 때만 교체). 저장 후 폼은 비운다.
- "저장된 내 취향" 카드의 × 로 항목 하나씩 삭제한다.
- 저장된 취향은 AI 추천(UI-11)의 기본 조건이 된다.

**2) 입력 · 결과**: `{ keywords[], categories[], price_range }` → 저장된 취향

**3) 검증**
- 빈 폼 저장 불가: "저장할 관심사 키워드 · 카테고리 · 가격대를 입력하거나 선택해 주세요." ✅ 프론트
- 📌 키워드 최대 10개, 카테고리 8종, 가격대 5구간 (Q3)

**4) 예외**: 저장 실패 → 오류 안내 · 삭제 실패 → 화면에서 지운 항목을 되돌림 ✅ 프론트

**5) 데이터 · API**: `user_preferences` · `GET/PUT /me/preferences`

**6) FastAPI 구현 항목** 🔧: 키워드 공백 제거 · 중복 제거 · 개수 제한, 허용 카테고리 · 가격대 값 검증
