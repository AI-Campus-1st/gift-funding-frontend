## 6. 후원 · 축하 메시지 (F-08, F-10, F-14)

### 6.1 후원하기 (UI-19 → UI-20, API D1)

**1) 규칙 · 흐름** (F-08 후원 진행 순서)
1. 친구 펀딩 상세에서 선물을 고른다. 목표 금액 · 달성률 · 구매 링크를 본다(모금액 · 남은 금액은 안 보임).
2. 금액: 추천 버튼 **5,000원 · 10,000원 · 30,000원** 또는 직접 입력. ✅ 프론트
3. 축하 메시지(선택): 직접 쓰거나 추천 문구 4개 중 하나를 눌러 자동 입력, 수정 · 삭제 가능. ✅ 프론트
4. "{금액}원 후원하기" → 서버가 펀딩 상태 · 남은 금액을 최신 기준으로 검증 → 후원 + 메시지를 함께 저장.
5. 성공하면 후원 완료 화면으로 자동 이동한다. 별도 메시지 작성 화면은 없다.
6. 같은 사람이 같은 선물에 **새 요청으로** 여러 번 후원할 수 있다. 같은 요청의 재전송은 한 번만 처리한다.

**2) 입력 · 결과**: `{ gift_id, amount, message, idempotency_key }` → `201 { donation_id }`

**3) 실행 조건 · 검증** (서버 처리 순서 — API_SPEC 3.4)

| 순서 | 조건 | 결과 | 위치 |
|---|---|---|---|
| 0 📌 | 멱등 키가 비었거나 64자 초과 (화면은 항상 36자 키를 만들어서 생기지 않음, 2026-10-19 확정) | `400` "잘못된 요청이에요. 다시 시도해 주세요." | 🔧 백엔드 |
| 1 | 같은 (후원자, 멱등 키) 요청이 이미 있음 | 이전 `donation_id` 반환, 새로 저장 안 함 | ✅ Mock → 🔧 UNIQUE |
| 2 | 후원자 권한 (그룹 참여자 · 📌 Q15 생일자 본인은 후원 불가) | `403` "본인 펀딩은 내 펀딩 메뉴에서 관리해 주세요." | ✅ 프론트(본인 펀딩은 친구 펀딩 화면에 안 보임) ✅ Mock |
| 3 | 금액 ≤ 0 · 정수 아님 | `400` "0원보다 큰 금액을 입력해 주세요." | ✅ 프론트(버튼 비활성) ✅ Mock |
| 4 | 펀딩이 진행 중이 아님 | `409 FUNDING_NOT_ACTIVE` "진행 중인 펀딩이 아니라 후원할 수 없어요." | ✅ Mock |
| 5 | 메시지 길이 초과 📌 Q4 200자 | `400` "축하 메시지는 200자 이내로 작성해 주세요." | ✅ 프론트 ✅ Mock |
| 6 | 남은 금액 0 (100% 달성) | `409 GOAL_REACHED` "후원이 마감된 선물입니다." | ✅ 프론트(버튼 비활성) ✅ Mock |
| 7 | 금액 > 남은 금액 | `409 EXCEEDS_REMAINING` + `max_available` "현재 이 선물에는 최대 {금액}원까지 후원할 수 있습니다. 후원 금액을 수정해 주세요." | ✅ Mock |
| 8 | 저장 | 후원 + (메시지가 있으면) 메시지 | ✅ Mock → 🔧 트랜잭션 |

**4) 예외 · 오류 처리**
- 실패해도 입력한 금액과 메시지를 유지한다. ✅ 프론트
- 서버가 명확히 거절한 경우 다음 요청은 새 멱등 키로 보낸다. 네트워크 실패처럼 결과를 모를 때는 같은 키로 다시 보낸다. ✅ 프론트
- 처리 중 다시 누를 수 없다. ✅ 프론트 · 변경 요청은 자동 재시도하지 않는다. ✅ 프론트(TanStack Query 설정)
- 📌 **확정 (Q5)**: 후원 금액은 **1원 단위**, 최소 **1원**. 최대는 그 선물의 남은 금액 (넘으면 `EXCEEDS_REMAINING`). (✅ 프론트 · ✅ Mock 이미 이렇게 동작)

**5) 데이터 · API**: `donations`, `messages`, `gifts` · `POST /donations`

**6) FastAPI 구현 항목** 🔧
- 트랜잭션 안에서 선물 행 `SELECT … FOR UPDATE` → 최신 합계(후원 + 이월) 계산 → 검증 → 저장
- `(supporter_id, idempotency_key)` UNIQUE 위반 시 기존 결과 반환 (동시 재전송 대비)
- ⚠️ 같은 키 확인은 **다른 모든 검사보다 먼저** 한다. 첫 요청 성공 뒤 선물이 마감되거나 펀딩이 끝나도, 재전송은 `409`가 아니라 기존 성공 응답(`201 { donation_id }`)을 받는다 (2026-10-19 명시)
- 메시지 저장 실패 시 후원도 롤백
- 동시 후원 테스트(pytest): 남은 금액보다 큰 합의 동시 요청 → 초과 없음

**현재 구현**: ✅ 프론트(금액 입력 · 추천 버튼 · 메시지 카드 · 멱등 키 · 실패 시 유지) · ✅ Mock(검증 순서 · 문구) · 🔧 백엔드(잠금 · 트랜잭션 · DB 제약)

### 6.2 후원 완료 · 내 후원 내역 (UI-20, UI-21, API D2 · D3)

- 본인 후원만 볼 수 있다. 다른 사람 후원 ID는 `403`. 같은 선물에 여러 번 후원하면 각각 표시한다.
- 표시: 후원 대상(펀딩 · 생일자) · 선물 · 본인 금액 · 일시 · 처리 상태(현재 `completed`만, 모의 후원).
- 🔧 백엔드: 본인 확인 쿼리. 실결제 도입 시 상태 값 확장(미정).

### 6.3 축하 편지함 (UI-27, API D4)

**1) 규칙**
- 메시지는 그 펀딩의 **생일자만** 읽는다. 다른 후원자는 볼 수 없다. (F-14)
- 작성자 이름은 계정 실명이다. 익명 · 별명 없음. 후원 금액은 표시하지 않는다.
- 📌 펀딩 상세에서 들어가면 **그 펀딩 메시지만**, 마이페이지에서 들어가면 **전체** 메시지.

**2) 입력 · 결과**: `?funding_id=`(선택) → `ReceivedMessageDto[] { author_name, content, funding_name, gift_name, created_at }` 최신순

**4) 예외**: 다른 사람 펀딩 지정 `403`

**6) FastAPI 구현 항목** 🔧: 메시지 → 후원 → 펀딩 조인으로 생일자 확인, 작성자 이름은 `users.name`에서 조회
